# 멘토링 5회차 (2026-10-30)

원본: Gemini 회의록 (Google Docs, 팀 공유 문서). 아래는 이 레포의 작업과 관련된 내용만 정리했다.

## 보고한 것

- 팀 레포를 만들고, 각자 낸 신기능을 프로토타입에서 토글로 켜 볼 수 있게 했다.
- 신기능 제안서를 이슈로 올리면 CEO·개발자 관점 리뷰가 자동으로 돈다.
- PR마다 Vercel 미리보기 링크가 붙어서, 제안한 사람이 자기 기능을 먼저 확인하고 고칠 수 있다.
- gstack을 참고하되 패션 커머스에 필요한 것만 남겨 가볍게 만들었다.

## 멘토 피드백

### 생산성을 수치로

- 이런 환경으로 협업하는 것 자체가 AX스러운 PM 역할이다. 이런 시스템을 가진 주니어라면 시니어가 데려가지 않을 이유가 없다.
- 지난주와 이번 주에 일하는 방식, 걸린 시간, 품질 검증 방식이 어떻게 달라졌는지 이해하기 쉬운 수치로 정리해 포트폴리오에 넣어라.
- 한 사람이 여러 프로덕트를 동시에 돌리는 구조와, 다른 프로덕트를 여러 PM과 함께 하는 구조도 고민해 보라.

### 시나리오로 보여주는 데모

- 기능을 하나씩 눌러 보며 설명하는 데모는 재미가 없다.
- 어떤 사용자가 어떤 욕구로 들어와서 어떤 순서로 문제를 해결하는지 시나리오를 여러 개 쓰고, 그대로 클릭해 따라갈 수 있는 데모를 만들어라.
  - 멘토 예시: 홈 검색 → AI 영역 펼치기 → 칩 더 보기 → 필터 → SRP·PDP 옵션 선택
- 링크만 있으면 누구나 시나리오별로 해볼 수 있어야 한다. Claude Artifact를 추천한다. Vercel도 괜찮고, TestFlight 앱까지 만들면 가장 좋다.

### 문서 가독성

- 지금 MD 문서는 텍스트 불릿 위주라 계층이 없어서 AI만 알아볼 수 있는 문서처럼 보인다. 면접관이 보면 "AI가 다 쓴 거죠?"로 끝난다.
- 표와 이미지를 넣어라. MD에서도 이미지 참조가 된다.
- Mermaid로 플로우차트, 시퀀스 다이어그램을 그려라.
- 디테일한 기획안은 HTML 버전도 같이 만들어라. AI가 가장 잘 읽는 문서가 MD와 HTML이다.

### 데모에서 나온 지적

- 랭킹 탭에서 기준 옷으로 거르면 원래 랭킹 번호를 그대로 써서 번호가 빈다. 보는 사람은 1, 2, 3 순서를 기대한다.
- 코디북과 "내 옷이랑 맞춰보기"가 둘 다 무드보드처럼 보인다. 지금 하나의 UX로 합치는 중이라고 공유했다.

## 참고: 질문에 대한 답

- 기능 도입 결정은 회사마다 다르다.
  - 무신사: 투페이저 → 팀 리더·EM 설득 → GMV 기여도로 C레벨 비딩 → PRD·디자인 → 대표 리뷰. AI 기능은 비용과 속도를 계산해 두지 않으면 개발 리더에게 바로 기각된다.
  - 코스: PM·디자이너·엔지니어·데이터 사이언티스트 스쿼드가 오너십을 갖고, 스쿼드가 동의하면 바로 개발한다.
- 비즈니스 임팩트 예측도 회사마다 다르다.
  - 29CM·쿠팡은 A/B 테스트가 필수, 무신사는 A/B 테스트 없이 직관으로 오픈한다.
  - A/B 테스트가 없으면 DID(기간 차이)나 가설 기반 예측을 쓴다.
  - 회사 JD를 보고, 시뮬레이션 데이터로 코호트·퍼널 분석을 Claude로 직접 돌려 보라.
- 문제 정의에서 솔루션으로 넘어가기 어려울 때: 동종 서비스를 직접 써 보며 불편한 점을 찾고, Tree of Thoughts로 여러 방향을 AI와 탐색한 뒤 좋은 조합을 프로토타입으로 검증하라.
