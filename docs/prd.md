# PRD: DANGJANG

무엇을, 누구를 위해, 왜 만드는지 정한다. 어떻게 동작하는지는 정책(`docs/policy/README.md`)이 정한다. 화면에서 어떻게 보이는지는 디자이너와 따로 정한다. 확정된 내용만 두고, 정하지 않은 것은 `docs/open-questions.md`에 둔다.

## 1. 한 줄 정의

DANGJANG(당신의 옷장)은 0에서 1로 새로 만드는 패션 커머스 서비스다. 다른 패션 커머스와의 차별점은 옷장이다. 잘 맞는 내 옷을 옷장에 담으면, 사기 전에 상품의 부위별 핏을 그 옷과 비교해 알려 준다.

## 2. 문제

체형 정보를 꼼꼼히 확인하는 Gen Z는 키·몸무게가 비슷한 사람의 후기를 찾을 수는 있지만, 신체 비율과 체형이 달라 그 후기가 내 핏을 예측해 주지 못한다. 그래서 확인을 거쳤는데도 실패를 반복하고, 실패한 옷은 반품되지 않은 채 옷장에 쌓인다. (팀 문제정의 v3)

| 근거 | 결과 |
|---|---|
| 최근 6개월에 3벌 이상 실패한 사람 | 핏 확인형 13명 중 6명, 나머지 11명 중 1명 |
| 체형 필터를 이미 쓰는 사람 | 핏 확인형 13명 중 8명. 쓰는데도 실패한다 |
| 정보 입력 의향 | 핏 확인형 13명 중 12명. 인터뷰에서는 쓸모가 보일 때만 입력했다 |
| 실패한 옷을 반품한 사람 | 인터뷰 4명 중 0명 |

표본은 설문 24명, 인터뷰 5명이다. 일반화하지 않고, 확실히 겪는 사람의 문제를 깊게 판다. 자세한 근거는 `docs/research/README.md`.

## 3. 타깃

**핏 확인형.** 사기 전에 "이 옷이 내 몸에 맞나"(사이즈, 비율, 체형)를 확인하려는 사람이다. 후기에서 작성자 키·몸무게를 먼저 보거나 앱 필터를 쓴다. 설문 24명 중 13명.

실물 확인형(색감·옷감·품질을 확인하려는 사람)도 팀이 정의했지만, 지금 해결 방향은 핏 확인형에 맞춘다.

## 4. 해결 방향

내 옷 기준 핏 예측. 이미 잘 맞는 내 옷(기준 옷)과 상품 실측을 부위별로 비교해 사이즈를 추천한다. 중간발표에서 선정했다.

| 기능 | 정책 |
|---|---|
| 옷장 등록 | REG |
| 기준 옷 | BASE |
| 사이즈 비교와 추천 | REC |
| 구매 확정과 옷장 담기, 교환 재추천 | ORD |
| 입점 브랜드의 치수 데이터와 보정 | CAL, PRD-02 |

## 5. 성공 측정

### 핵심 지표
그 상품과 세부 종류가 같은 기준 옷이 있는 사용자의 상품 상세 조회 중, 비교가 표시되고 추천 사이즈를 고른 비율. 자동 비교(CMP-04)로 본 조회는 넣지 않고 따로 본다.

### 반품 감소를 효과 지표로 쓰지 않는다
실패한 옷은 반품되지 않아서(인터뷰 4명 중 0명) 반품률에 효과가 드러나지 않는다. 전환과 재구매 신뢰를 앞세우고, 왜 반품률로 잴 수 없는지를 발표에서 설명한다.

### 추천이 맞는지 재는 방법
- 정답표로 추천 규칙을 잰다(REC-11).
- 주문에 추천 사이즈, 산 사이즈, 추천 상태를 남긴다(ORD-04).

### 유저 테스트
합격선은 실행 전에 숫자로 정한다. 예: 참가자 10명 중 7명 이상이 도움 없이 첫 옷을 등록한다.

## 6. 범위

### 발표까지 실제로 동작하게 할 것
옷장 등록, 기준 옷, 사이즈 비교와 추천, 구매 확정과 옷장 담기, 교환 재추천.

### 흉내만 낼 것
주문서 입력, 탈퇴, 쿠폰, 결제 실패, 장바구니 편집, 검색 필터, 로그인·가입 세부, 알림 설정, 홈 운영, 마이 메뉴, 로그아웃, 검색, 주문 완료.

화면은 보여 주되 규칙은 정하지 않는다. 이 화면들도 DANGJANG이 직접 만들 기능이지만, 차별점이 아니라서 일반적인 패션 커머스 방식을 따른다. 발표에서는 차별점인 옷장에 집중한다고 설명한다.

### 정책으로만 둘 것
입점과 어드민 화면은 데모에 만들지 않는다. 규칙은 정책(CAL, PRD-02)에 둔다.

### 사진 측정
보조 등록 수단으로 소개하고, 핵심 기능으로 내세우지 않는다. 멘토는 3~4cm 오차가 신뢰를 깎고 구현 비용이 크다며 우선순위에서 빼라고 했다(멘토링 3회차).

### 로드맵
- 추가 기능 아이디어는 지금 기능의 유저 검증 뒤 로드맵으로 정리한다(멘토링 4회차).
- 사진 측정 운영안: AI가 먼저 대략적인 값을 보여 주고, 담당자가 정해진 기간 안에 정확한 값으로 바꾼다. 인건비 계산이 필요하다(멘토링 3회차).
