# DANGJANG 서비스 정책

> 새 구조로 옮기는 중이다(10/27). 분류 체계, 측정 방식, 보정은 `01-기본-정책.md`가 기준이고, 용어는 `docs/glossary.md`가 기준이다. 이 문서의 나머지는 기본 정책 위에서 다시 본 뒤 옮긴다(`README.md`).

DANGJANG(당신의 옷장)은 0에서 1로 새로 만드는 패션 커머스 서비스이고, 차별점은 옷장이다. 다른 커머스 앱에 붙이는 기능이 아니라 상품, 입점 브랜드, 주문, 어드민을 모두 직접 운영한다. 출시 전이라 기존 상품은 없고, 모든 상품은 입점 절차를 거쳐 들어온다.

이 문서는 DANGJANG이 어떻게 동작해야 하는지를 한곳에 모은 문서다. 기획, 디자인, 개발, 리뷰가 모두 이 문서를 기준으로 삼는다. 데모가 이 문서와 다르면 데모를 고친다.

- 기준일: 2026-10-27
- 근거: `logs/decision-log.md`, 세 관점 리뷰(`reviews/2026-10-26-*-demo-v14.md`), 출시 수준 점검 목록(`reviews/2026-10-26-출시수준-점검목록.md`), 멘토링 기록
- 추천 규칙을 정할 때 검토한 선택지: `docs/policy/결정지-2026-10-26-추천규칙.md`

## 0. 원칙

모든 규칙은 아래 원칙을 따른다. 규칙이 없는 상황을 만나면 원칙으로 판단한다.

1. **정확하지 않으면 정확하지 않다고 말한다.** 추정값, 부족한 데이터, 애매한 추천은 화면에 그대로 드러낸다. 틀린 확신보다 "모른다"가 신뢰를 덜 잃는다.
2. **조용한 실패는 없다.** 잘못된 입력, 품절, 비교 불가는 사용자에게 보이고, 다음에 할 일을 알려 준다.
3. **사용자가 입력한 정보만 쓴다.** 사용자가 직접 넣지 않은 신체·옷 정보는 가져오지 않는다.
4. **수고보다 쓸모를 먼저 보여 준다.** 사용자는 쓸모가 보일 때만 정보를 입력한다(인터뷰 5/5).
5. **한 뜻은 한 말과 한 색으로.** 같은 판정을 화면마다 다른 단어나 색으로 말하지 않는다.
6. **정확도를 낮춰서 부담을 줄이지 않는다** (10/27). 정확한 추천이 서비스의 정체성이다. 사용자의 부담은 필수 항목을 줄여서가 아니라 데이터를 가져오는 방법(구매 확정, 상품 링크, 입점 데이터)으로 줄인다. 상품 데이터의 정확성은 입점과 어드민에서 지킨다(10장).

## 1. 용어

| 용어 | 정의 | 상태 |
|---|---|---|
| 기준 옷 | 비교의 기준이 되는 잘 맞는 내 옷. 세부 종류 기준 옷과 대분류 기준 옷 두 층이 있다(3장) | ✅ 10/27 |
| 대분류 | 상의, 하의, 아우터 3가지 | ✅ 팀 합의 |
| 세부 종류 | 사이즈 비교의 분류. 15가지이고 사용자가 고르고 화면에 보인다. 아래 1.1 표 | ✅ 팀 합의 |
| 세부 종류 기준 옷 | 세부 종류마다 하나씩 둘 수 있는 기준 옷. 그 세부 종류 상품은 이 옷과 비교한다 | ✅ 팀 합의, 10/27 |
| 대분류 기준 옷 | 상의·하의·아우터마다 하나인 상위 기준 옷. 상품의 세부 종류 기준 옷이 없을 때만 쓴다 | ✅ 팀 합의, 10/27 |
| 비교 옷 | 지금 보고 있는 상품 하나와 견줘 보려고 잠깐 고른 옷. 기준 옷을 바꾸지 않는다 | ✅ 10/27 |
| 치수 양식 | 세부 종류마다 어떤 부위를 재는지 정한 내부 양식 8가지. 사용자에게 보이지 않고, 기준 옷의 단위도 아니다. 아래 1.1 표 | ✅ 10/27 |
| 실측 | 옷을 평평하게 놓고 잰 단면 치수, cm | ✅ |
| 핵심 부위 | 추천을 내려면 꼭 있어야 하는 부위. 치수 양식마다 정한다(1.2). 비교는 핵심 부위만이 아니라 두 옷 모두 잰 부위 전부로 한다(4.3) | ✅ 10/27 |
| 품 부위 · 길이 부위 | 옷을 펴 놓고 **가로로 재면 품, 세로로 재면 길이**다. 품: 가슴·어깨·암홀·밑단·소매부리·허리·엉덩이·허벅지. 길이: 총장·소매·전체소매·밑위 | ✅ 10/27 |
| 몸통 품 부위 | 품 부위 중 재는 위치가 옷 길이와 상관없는 부위. 상의·아우터는 가슴·어깨·암홀, 하의는 허리·엉덩이·허벅지. 밑단·소매부리는 길이에 따라 재는 위치가 바뀌어(반팔 소매부리는 팔뚝, 긴팔은 손목) 들어가지 않는다 | ✅ 10/27 |
| 치수 출처 | 판매처 실측 / 내가 잰 값(직접 입력·사진 측정) / 추정값(판매처가 주지 않은 칸을 비율로 채운 값) | ✅ 10/26 |
| 구매 확정 | 배송 완료 뒤 사용자가 확정한 상태. 옷장 담기를 묻는 시점 | ✅ 10/22 |

### 1.1 대분류와 세부 종류

| 대분류 | 세부 종류 (15가지, 팀 합의) | 치수 양식 (내부용) |
|---|---|---|
| 상의 | 긴팔 셔츠, 긴팔 티셔츠, 후드티 | 긴팔 상의 |
| 상의 | 반팔 셔츠, 반팔 티셔츠 | 반팔 상의 |
| 하의 | 긴바지 | 긴바지 |
| 하의 | 반바지 | 반바지 |
| 하의 | 긴치마 | 긴치마 |
| 하의 | 짧은 치마 | 짧은 치마 |
| 아우터 | 가디건, 점퍼/자켓, 숏코트, 숏패딩 | 짧은 아우터 |
| 아우터 | 롱코트, 롱패딩 | 긴 아우터 |

- 사이즈 비교와 기준 옷은 **세부 종류 단위**다. 치수 양식은 등록 화면에 어떤 치수 칸을 보여 줄지만 정한다.
- 세부 종류를 고르지 않으면 상의는 긴팔 티셔츠, 하의는 긴바지, 아우터는 점퍼/자켓으로 본다.
- 출처: 데모 코드의 세부 종류 표(`SUBS`)와 치수 양식 이름(`GROUP_N`). 지금 데모는 치수 양식 8개를 기준 옷 단위로 쓰고 있어 이 정책과 다르다(10/27 변경).

### 1.2 핵심 부위 ✅ (10/27)

| 치수 양식 | 핵심 부위 | 품 부위 | 길이 부위 |
|---|---|---|---|
| 긴팔 상의, 짧은 아우터, 긴 아우터 | 총장 · 가슴 · 어깨 · 소매 | 가슴 · 어깨 | 총장 · 소매 |
| 반팔 상의 | 총장 · 가슴 · 어깨 | 가슴 · 어깨 | 총장 |
| 긴바지, 반바지 | 허리 · 엉덩이 · 밑위 · 총장 | 허리 · 엉덩이 | 밑위 · 총장 |
| 긴치마, 짧은 치마 | 허리 · 엉덩이 · 총장 | 허리 · 엉덩이 | 총장 |

- 핵심 부위가 하나라도 없으면 추천하지 않고 "비교 부위 부족" 상태가 된다(4.2). 기준 옷도 될 수 없다(2.5).
- 브랜드는 핵심 부위를 모든 사이즈에 반드시 넣는다(10.1). 사용자가 직접 입력할 때도 핵심 부위는 필수다(2.2).
- 어깨선 모양(드롭숄더, 래글런 등)과 상관없이 같은 치수 양식이면 핵심 부위가 같다 (10/27). 어깨선 모양으로 세부 종류를 더 나누지 않는다.
- 반팔 상의 양식에는 지금 어깨 칸이 없다(데모 `GPARTS`). 어깨 칸을 추가한다.
- 고른 이유: 길이와 품을 둘 다 잡는다. 인터뷰이 B는 실측을 보고도 바지 밑위·기장에서 실패했다. 몸에 붙는 바지·치마는 엉덩이가 맞지 않으면 입을 수 없다. 모두 일반 사이즈표에 거의 늘 있는 부위라 브랜드 부담이 작다.
- 10/26의 "상의 총장·가슴, 하의 허리·총장"(등록 화면 필수 칸 `NEED`를 그대로 가져온 것)을 대체한다.

## 2. 옷장 등록

### 2.1 무엇을 등록하나

- ✅ **잘 맞는 옷만 등록한다.** 등록할 때 핏을 묻지 않는다. 안 맞는 옷 관리 기능은 두지 않는다. (10/22, 멘토링 4회차)
- ✅ **이 규칙을 사용자에게 알린다** (C2, 10/27). 첫 등록 화면과 옷장 빈 상태에 "잘 맞아서 자주 입는 옷을 넣어 주세요"를 보여 준다. 이미 넣은 옷을 빼는 방법은 삭제로 충분하다.

### 2.2 등록 경로

| 경로 | 정책 | 상태 |
|---|---|---|
| 구매 확정 | 배송 완료 → 구매 확정 → "옷장에 담을까요?" [나중에 / 담기]. 주문 내역에서도 담을 수 있다 | ✅ 10/22 |
| 상품 링크 | 판매처 실측을 가져온다. 실패하면 실패 이유를 보여 주고, 사이즈표 붙여넣기와 직접 입력을 버튼으로 권한다. 지원 쇼핑몰 목록은 보여 주지 않는다 (C4) | ✅ 10/27 |
| 구매내역 캡처 | 캡처에서 상품을 찾아 실측을 가져온다. 못 찾으면 링크 실패와 같은 방식으로 안내한다 (C7) | ✅ 10/27 |
| 사진 촬영 | 아래 2.3 | ✅ 10/27 |
| 직접 입력 | 핵심 부위는 필수, 나머지는 선택. 사이즈표 붙여넣기를 지원한다 | ✅ |

### 2.3 사진 측정

- ✅ **지원 범위를 긴팔 셔츠, 긴팔 티셔츠, 후드티, 긴바지로 좁힌다** (C1, 10/27). 지금 엔진은 상의와 바지만 재고, 반팔·치마·롱아우터에서는 부위가 비거나 범위 밖으로 나온다. 다른 세부 종류는 사진 촬영 입구에서 "이 종류는 직접 입력해 주세요"로 안내한다.
- ✅ **발표에서 사진 측정을 핵심 기능으로 내세우지 않는다** (10/27). 보조 등록 수단으로 소개한다. 멘토는 3~4cm 오차가 신뢰를 깎고 구현 리소스가 크다며 우선순위에서 빼라고 했다(멘토링 3회차). 대안으로 "AI가 먼저 대략적인 값을 보여 주고, 담당자가 정해진 기간 안에 정확한 값으로 바꾼다"는 운영 방식을 로드맵에 둔다. 인건비 계산이 필요하다.
- ✅ 측정에 실패하면 숫자를 지어내지 않고, 원인과 수동 대안을 보여 준다 (이미 그렇게 동작함).

### 2.4 치수 입력 검증

- ✅ **검증은 한 곳에서 한다** (A1, 10/26). 등록, 사진 결과, 정보 수정이 같은 검증을 쓴다.
- ✅ 쉼표는 소수점으로 읽는다. "56cm"처럼 단위가 붙은 값도 읽는다.
- ✅ 부위별 범위와 부위 간 관계(밑위 < 총장, 허리 < 엉덩이)를 본다. 틀리면 **저장을 막고**, 그 칸 테두리와 칸 아래 글자로 이유를 보여 주고, 첫 오류 칸으로 이동한다.
- ⬜ 부위별 범위 값. 데모 상품 실측 분포로 초안을 만든 뒤 팀이 확인한다.
- ⬜ 둘레로 보이는 값(단면의 2배 근처)을 반으로 나눠 줄지.

### 2.5 실측 없는 옷

- ✅ **실측 없는 상품을 사서 담을 때는 "치수를 적어 주세요" 화면으로 보낸다.** 핵심 부위가 찰 때까지 기준 옷으로 쓰지 않는다. (10/26, 엔지니어 리뷰에서 찾은 버그)

### 2.6 치수 출처

- ✅ **치수 출처(판매처 실측 / 내가 잰 값)를 화면에서 구분하지 않는다** (C5, 10/27). 추정값만 따로 표시한다(4.3).
- ⬜ 출처별로 오차를 다르게 둘지.

### 2.7 그 밖의 등록 규칙

- ✅ 세부 종류를 고르지 않으면 어떤 종류로 보고 비교하는지 표시한다. 예: "긴팔 티셔츠로 보고 비교해요" (D2, 10/27). 세부 종류는 필수가 아니다.
- ✅ 종류를 바꿔도 같은 부위 값은 유지한다 (D3, 10/27).
- ⬜ 중복 등록: 무엇을 같은 옷으로 볼지, 막을지 알리기만 할지 (A6).

## 3. 기준 옷

### 3.1 두 층의 기준 옷 (팀 합의, 10/27)

- ✅ **세부 종류 기준 옷:** 세부 종류 15가지마다 하나씩 둘 수 있다.
- ✅ **대분류 기준 옷:** 상의·하의·아우터마다 하나. 그 대분류에 처음 등록한 옷이 자동으로 정해지고, 내 옷장 목록에서 바꿀 수 있다.
- ✅ 세부 종류에 처음 등록한 옷이 자동으로 그 세부 종류의 기준 옷이 된다 (10/27). 내 옷장 목록에서 바꿀 수 있다.
- ✅ 핵심 부위가 없는 옷은 어느 기준 옷도 될 수 없다(2.5).
- ✅ 상의·하의·아우터 사이에서는 비교하지 않는다. 상의 상품을 아우터 기준 옷과 비교하지 않는다.

### 3.2 상품을 볼 때 어떤 기준 옷을 쓰나

```
상품의 세부 종류 기준 옷이 있나?
 ├─ 있음 → 그 옷과 비교 (모든 부위)
 └─ 없음 → 상품 대분류의 기준 옷이 있나?
            ├─ 있음 → 그 옷과 비교 (몸통 품 부위만, 화면에 표시)
            └─ 없음 → "이 종류의 기준 옷이 없어요" + 등록 안내
```

- ✅ **대분류 기준 옷으로 비교할 때는 몸통 품 부위만 비교한다** (10/27). 가슴·어깨·암홀, 허리·엉덩이·허벅지만 보고, 총장·소매 같은 길이 부위와 밑단·소매부리는 뺀다. 세부 종류가 달라 기장의 뜻이 다르기 때문이다(예: 긴바지 기준으로 짧은 치마를 보면 총장은 항상 "짧아요"가 된다).
- ✅ **화면에 어떤 기준으로 비교했는지 알린다** (10/27). 예: "반팔 티셔츠 기준 옷이 없어서 상의 기준 옷(긴팔 셔츠)으로 비교했어요 · 기장은 비교하지 않았어요". 반팔 티셔츠 기준 옷을 등록하는 버튼을 함께 둔다.
- 🟡 대분류 기준 옷으로 비교할 때는 상품 치수 양식의 **품 핵심 부위가 모두** 있어야 추천한다(1.2). 예: 긴팔 티 기준으로 반팔 셔츠를 보면 가슴·어깨, 긴바지 기준으로 치마를 보면 허리·엉덩이. 없으면 "비교 부위 부족" 상태가 된다(4.2). (10/27, 핵심 부위 결정에 맞춰 고침)

### 3.3 기준 옷 바꾸기

- ✅ **기준 옷과 비교 옷은 다른 개념이다** (10/27). 기준 옷은 그 세부 종류(또는 대분류)의 모든 추천에 쓰이는 옷이고, 비교 옷은 지금 보고 있는 상품 하나와 견줘 보는 옷이다. 비교 옷을 바꿔도 기준 옷은 바뀌지 않는다.
- ✅ **상품 상세의 "교체하기"는 비교 옷만 바꾼다** (A4·B13, 10/27). 이 상품에서만 고른 옷과 비교하고, 다른 상품의 추천은 그대로다.
- ✅ **내 옷장 > 옷 상세에서는 기준 옷을 바꿀 수 없다** (10/27). "기준 옷 바꾸기"를 없앤다.
- ✅ **기준 옷이 바뀌는 경로에서는 확인을 받는다** (A4, 10/27). 대상: 등록 때 "기준 옷으로" 체크, 기준 옷 치수 수정, 기준 옷의 세부 종류를 바꾸는 경우. 확인창에는 치수 차이를 보여 준다.
- ✅ **등록한 뒤 기준 옷은 내 옷장 목록에서 바꾼다** (10/27). 목록에서 세부 종류별 기준 옷과 대분류 기준 옷을 고르는 곳을 둔다. 바꿀 때는 확인창에 지금 기준 옷과 새 기준 옷의 치수 차이를 보여 주고, 바꾼 뒤에는 실행 취소 토스트로 되돌릴 수 있게 한다. 기준 옷을 바꾸는 곳은 이곳과 등록 때 체크 두 곳뿐이다.
- ⬜ 기준 옷을 지웠을 때 누가 이어받나: 등록 순 / 치수가 가장 가까운 옷 / 사용자 선택 (A4).
- ✅ 옷 삭제와 기준 변경은 실행 취소 토스트로 되돌릴 수 있게 한다 (A5, 10/27).
- ✅ **세부 종류별 기준 옷 현황은 상품 상세에서만 알린다** (D1, 10/27). 3.2의 안내 문구가 그 역할을 한다. 내 옷장에 15가지 현황판은 두지 않는다. 내 옷장 목록의 기준 옷 고르기는 옷이 있는 세부 종류와 대분류만 보여 준다.

## 4. 사이즈 비교와 추천

모두 ✅ 확정 (10/26). 검토한 선택지는 결정지에 있다.

### 4.1 계산 구조

- 추천 계산은 함수 하나(`recommend(상품, 기준 옷)`)가 맡는다. 홈, 상품 상세, 옵션 시트, 주문서가 모두 이것만 쓴다.
- 결과는 사이즈, 부위별 차이, 비교한 부위 수, 상태를 함께 돌려준다.

### 4.2 추천 상태

| 상태 | 언제 | 화면 문구 예시 |
|---|---|---|
| 추천 | 아래 어느 것에도 해당하지 않을 때 | "M 추천" |
| 두 사이즈 사이 | 1·2위 점수 차이가 작을 때 (초안: 10% 이내) | "M과 L 사이예요 · M은 기장이, L은 가슴이 맞아요" |
| 맞는 사이즈 없음 | 가장 가까운 사이즈도 핵심 부위 중 하나가 4cm를 넘게 **작을 때** | "맞는 사이즈가 없어요 · 가장 가까운 L도 가슴이 5cm 작아요" |
| 가장 맞는 사이즈 품절 | 1위 사이즈가 품절일 때 | "가장 잘 맞는 M은 품절이에요 · 다음은 L" |
| 모든 사이즈 품절 | 모든 사이즈가 품절일 때 | "모든 사이즈가 품절이에요" |
| 비교 부위 부족 | 세부 종류 기준 옷과 비교할 때 핵심 부위가 하나라도 빠졌거나, 대분류 기준 옷과 비교할 때 품 핵심 부위가 하나라도 빠졌을 때 | "비교할 치수가 부족해요" |

어느 상태든 대분류 기준 옷으로 비교했다면 3.2의 안내 문구를 함께 보여 준다.

크기만 큰 경우는 "맞는 사이즈 없음"이 아니다. 추천하되 "넉넉해요"를 보여 준다.

### 4.3 비교 규칙

| 규칙 | 내용 |
|---|---|
| 비교 대상 | 두 옷 모두 잰 부위만 비교한다. 빈 칸은 0으로 넣지 않고 점수에서 뺀다. 세부 종류가 다른 옷과 비교할 때는 그중 몸통 품 부위만 쓴다(3.2, 5.2.1) |
| 추정값 | 추천 점수에서 뺀다. 도식에는 점선으로 그리고 "추정"이라고 표시한다 |
| 최소 부위 | 치수 양식의 핵심 부위가 모두 있어야 추천한다(1.2) |
| 가중치 | 부위 이름에 붙인다. 품 부위 1.3, 길이 부위 1.0 (초안) |
| 작은 쪽 | 품 부위에서 작은 쪽 차이를 1.5배로 본다. 길이 부위는 같게 본다 (초안) |
| 허용 오차 | 2cm 이내면 "비슷해요", 4cm를 넘으면 "커요·작아요". 10/30까지 유지하고, 정답표 결과를 보고 v3에서 부위별 값을 정한다 |
| 핏 의도 | 오버핏·신축성은 추천에 반영하지 않는다. 오버핏 상품에는 "오버핏이라 크게 나오는 옷이에요"를 안내한다 |
| 후기 | 후기는 추천에 반영하지 않는다 (B14, 범위 밖) |

"(초안)" 값은 근거가 아직 없다. 정답표(4.4)의 맞은 개수를 보고 조정하고, 조정하면 이 문서와 결정 기록을 함께 고친다.

### 4.4 정답표

- 상품 실측·기준 옷 쌍 20~30개에 기대 결과(사이즈와 상태)를 적는다. 세부 종류 기준 옷으로 비교하는 경우와 대분류 기준 옷으로 넘어가는 경우를 모두 넣는다.
- 데모 안의 확인 함수로 한 번에 돌려 맞은 개수를 본다.
- v1과 v2를 같은 표로 잰다. 규칙을 바꿀 때마다 다시 돌린다.

### 4.5 홈의 옷장 기준 추천

- 상세와 같은 함수를 쓰고 품절 사이즈를 뺀다.
- 퍼센트("92% 비슷해요")는 쓰지 않는다. 종합 판정 단어로 보여 준다.
- ⬜ 결과가 없을 때 기준을 완화할지, "전체보기"를 전용 목록으로 보낼지 (E13).

## 5. 표현

### 5.1 판정 용어 ✅ (10/26)

| 층 | 쓰는 말 |
|---|---|
| 종합 판정 | 비슷해요 / 커요 / 작아요 |
| 길이 부위 | 길어요 / 짧아요 |
| 품 부위 | 넉넉해요 / 타이트해요 |

"넓어요", "딱 맞아요", 퍼센트는 쓰지 않는다.

### 5.2 비교 도식 ✅ (10/26)

- 어느 옷인지는 선 모양으로만 구분한다. 내 옷은 회색 점선, 상품은 검정 실선.
- 얼마나 다른지는 뱃지 색으로만 보여 준다. 가장 큰 차이의 뱃지를 크게 그린다.
- 데이터가 없는 부위는 "정보 없음"으로 그린다. 상대 옷 값으로 채워 그리지 않는다.

### 5.2.1 같은 종류와 다른 종류의 비교 화면 ✅ (10/27)

비교에 쓰는 옷(기준 옷이든 "교체하기"로 고른 비교 옷이든)과 상품의 **세부 종류**가 같은지로 화면을 나눈다.

| | 같은 세부 종류 | 다른 세부 종류 (같은 대분류) |
|---|---|---|
| 예 | 긴팔 티 기준 옷 → 긴팔 티 상품 | 반팔 티 기준 옷 → 긴팔 티 상품 |
| 비교하는 부위 | 두 옷 모두 잰 부위 전부 | 몸통 품 부위만 (1장) |
| 추천 사이즈 | 보여 준다 | 보여 준다 |
| 비교 도식 | 내 옷(회색 점선)과 상품(검정 실선)을 겹쳐 그린다 | **상품 도식만** 그린다. 내 옷 선은 그리지 않는다 |
| 부위별 판정 | 모든 비교 부위 | 몸통 품 부위에만. 나머지 부위는 상품 치수만 보여 준다 |
| 안내 | 없음 | 어떤 옷 기준으로, 무엇을 비교했는지 알린다 (3.2) |

- 다른 대분류의 옷과는 비교하지 않는다(3.1). "교체하기"의 옷 목록에도 같은 대분류 옷만 보여 준다.
- 같은 세부 종류인지는 세부 종류 15가지로만 판단한다. 치수 양식이 같아도(예: 긴팔 셔츠와 긴팔 티셔츠) 세부 종류가 다르면 다른 종류다.

### 5.3 디자인 기준

- ✅ 디자인 기준은 상품 상세 시안이다. 주 버튼은 초록. (10/22)
- ✅ **모든 화면을 상세 시안 토큰으로 통일한다** (디자인 리뷰, 10/27). 파란 `--fit`과 검정 주 버튼을 없앤다.
- ✅ **글자·버튼용 진한 초록을 하나 더 둔다** (10/27). 지금 초록 위 흰 글자 대비가 2.52:1로 기준(4.5:1)에 못 미친다. 넓은 면과 도식은 지금 초록을 유지한다. ⬜ 색 값은 디자이너가 고른다.
- ✅ 초록은 "주 행동"만 뜻한다 (10/27). "내 옷"이나 "비슷해요"를 초록으로 표시하지 않는다(5.2와 함께).

### 5.4 빈 상태

- ✅ 등록 전 비교 예시는 보여 주지 않는다 (10/27). 지금처럼 문구와 첫 등록 쿠폰으로 안내한다.

## 6. 구매와 주문

- ✅ 구매 확정 뒤에 옷장 담기를 묻는다. 반품한 옷은 담지 않는다. (10/22)
- ✅ **주문 상태는 하나의 값으로 관리한다** (엔지니어 리뷰, 10/27). `배송 중 → 배송 완료 → 구매 확정 → 옷장 담김` / `배송 완료 → 반품 신청`. 확정·반품·담기 전에 현재 상태를 확인한다. 지금은 반품 신청한 주문도 알림에서 옷장에 담을 수 있다(버그).
- ✅ **주문에 추천 사이즈, 산 사이즈, 추천 상태를 남긴다.** (10/26)
- ✅ 구매 확정 때 "사이즈가 맞았나요?"는 **이번에는 묻지 않는다.** 10/28 유저 테스트에서 답할 의향을 확인하고 다시 정한다. (10/26)
- ✅ 배송 완료 뒤 정해진 기간이 지나면 자동 확정하고, 다음 앱 실행 때 옷장 담기를 묻는다 (E4, 10/27). ⬜ 기간.
- ✅ 반품과 교환을 나누고, 교환할 때 기준 옷 기준으로 사이즈 추천을 다시 보여 준다 (E3, 10/27). 서비스 핵심과 직접 이어진다.
- ⬜ 장바구니에서 사이즈를 바꿀 때 추천을 보여 줄지 (E8).

## 8. 측정

- ✅ 정답표로 추천 규칙을 잰다(4.4).
- ✅ 주문에 추천 정보를 남긴다(6장).
- ✅ **핵심 지표:** 그 상품에 쓸 기준 옷(세부 종류 또는 대분류)이 있는 사용자의 상품 상세 조회 중, 비교가 표시되고 추천 사이즈를 고른 비율 (gstack CEO 리뷰, 10/27). ⬜ 보조 지표 2개(이용과 신뢰가 실제로 생기는지, 잘못된 추천이 늘지 않는지).
- ✅ "반품 감소"를 효과 지표로 내세우지 않는다 (10/27). 실패한 옷은 반품되지 않아서(인터뷰 0/4) 반품률에 효과가 드러나지 않는다. 전환과 재구매 신뢰를 앞세우고, 왜 반품률로 잴 수 없는지를 발표에서 설명한다.
- ✅ 유저 테스트 합격선은 실행 전에 숫자로 정한다 (10/27). 예: 참가자 10명 중 7명 이상이 도움 없이 첫 옷을 등록한다.

## 9. 범위

- ✅ 추가 기능 아이디어는 지금 기능의 유저 검증 뒤 로드맵으로 정리한다. (10/22)
- ✅ **발표까지는 핵심만 실제로 동작하게 한다** (CEO 리뷰, 10/27). 핵심: 옷장 등록, 기준 옷, 사이즈 비교와 추천, 구매 확정과 옷장 담기, 교환 재추천.
- ⛔ **흉내만:** 주문서 입력(E1), 탈퇴(E5), 쿠폰(E6), 결제 실패(E7), 장바구니 편집(E8), 검색 필터(E9), 로그인·가입 세부(E10), 알림 설정(E11), 홈 운영(E12), 마이 메뉴(E14), 로그아웃·검색·주문 완료(E15). 화면은 보여 주되 규칙은 정하지 않는다. 이 화면들도 DANGJANG이 직접 만들 기능이지만, 차별점이 아니라서 일반적인 패션 커머스 방식을 따른다. 발표에서는 차별점인 옷장에 집중한다고 설명한다.
- ⛔ **입점·어드민 화면은 데모에 만들지 않는다** (10/27). 규칙은 10장에 정책으로만 둔다.

## 10. 상품 실측 데이터 (입점과 어드민)

추천의 정확도는 상품 실측에서 시작한다. 출시 전이라 기존 상품은 없고, 모든 상품은 입점 절차를 거쳐 들어온다. 그래서 상품 데이터의 정확성은 사용자 화면이 아니라 입점과 어드민에서 지킨다(원칙 6).

### 10.1 입점할 때 받는 것

- ✅ **브랜드는 상품을 등록할 때 그 세부 종류의 핵심 부위를 모든 사이즈에 넣어야 한다** (10/27). 하나라도 비면 등록할 수 없다. 핵심 부위 목록은 1장을 따른다.
- ✅ **브랜드는 자기 측정 방식을 제출하고, 우리가 계산에서 맞춘다** (10/27). 브랜드에게 우리 방식으로 다시 재라고 하지 않는다. 측정 가이드를 주고 다시 재게 하는 것보다 브랜드 부담이 작아 입점이 현실적이다.
- 🟡 측정 방식은 입점 때 한 번 받고, 브랜드 안에서도 세부 종류마다 다를 수 있어 세부 종류 단위로 받는다. 받는 항목 (초안):

| 항목 | 고르는 것 |
|---|---|
| 단면 / 둘레 | 가슴·허리·엉덩이·허벅지·밑단을 단면으로 재는지, 둘레로 재는지 |
| 상의 총장 시작점 | 옆목점 / 뒷목 중심 |
| 어깨 | 어디서 어디까지 재는지 (예: 봉제선 끝에서 끝) |
| 소매 | 어깨 끝부터 / 뒷목 중심부터 |
| 하의 총장·밑위 | 허리 밴드를 넣어서 재는지 |

### 10.2 우리 기준으로 바꾸기

- ✅ **모든 상품 실측은 DANGJANG 기준(단면, cm, 1장 "실측")으로 바꿔서 비교한다** (10/27). 브랜드가 넣은 원래 값도 함께 보관한다.
- ✅ 바꾸는 규칙: 둘레는 2로 나눈다. 시작점이 다르면 그 차이만큼 더하거나 뺀다.
- ⬜ 시작점 차이 보정값(cm). 근거가 아직 없다. 초안을 정하고 정답표(4.4)의 맞은 개수로 조정한다.
- 한계: 바꿀 수 있는 것은 **측정 방식의 차이**뿐이다. 같은 방식으로 재도 사람마다 생기는 오차는 남는다. 이 오차는 허용 오차(4.3)가 감당한다.
- 🟡 사용자가 직접 재는 값(직접 입력, 사진 측정)은 우리 기준대로 재도록 등록 화면에 재는 위치를 그림으로 보여 준다. 측정 가이드는 브랜드가 아니라 사용자에게만 둔다.

### 10.3 어드민 상품 등록 검사

- ✅ **상품은 검사를 통과해야 노출된다** (10/27). 판매자가 넣은 값이 틀리면 그 상품을 본 모든 사용자의 추천이 틀린다.
- ✅ **자동 검사가 먼저 보고, 걸린 상품만 담당자가 본다** (10/27). 모든 상품을 사람이 보면 인건비가 커진다(멘토링 3회차).
- ✅ 걸리면 노출을 보류하고, 담당자가 확인한 뒤 판매자에게 어느 사이즈의 어느 칸이 왜 걸렸는지 알리고 수정을 요청한다.
- 🟡 자동 검사 항목 (초안):

| 검사 | 걸리는 예 |
|---|---|
| 필수 부위 | 핵심 부위가 한 사이즈라도 비었다 |
| 사이즈 순서 | 사이즈가 커지는데 값이 줄어든다 |
| 정상 범위 | 세부 종류별 범위를 벗어난다. 2.4의 범위 값과 같은 표를 쓴다 |
| 부위 관계 | 밑위가 총장보다 길다, 허리가 엉덩이보다 크다. 2.4와 같은 규칙을 쓴다 |
| 측정 방식 | 둘레로 낸다고 했는데 단면 근처 값이다, 또는 그 반대 |
| 다른 상품과 비교 | 같은 세부 종류, 같은 사이즈 상품들과 크게 다르다 |

- ⬜ 담당자 확인 기한과 인건비. 멘토링 3회차 과제(운영 정책, 인건비)와 함께 정한다.
