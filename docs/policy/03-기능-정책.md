# 03. 기능 정책

옷장 등록, 비교와 추천, 구매와 주문, 개인정보의 규칙이다. 기본 정책(`01-기본-정책.md`)과 대상과 상태(`02-대상과-상태.md`) 위에 선다.

- 확정된 규칙만 둔다. 아직 정하지 않은 것과 초안 값은 `docs/open-questions.md`에 둔다.
- 화면 문구와 디자인은 정책이 아니라 디자이너와 따로 정한다. 이 문서는 무엇을 알려야 하는지만 정한다.

---

## 1. 옷장 등록 (REG)

### REG-01 잘 맞는 옷만 담는다는 것을 알린다
첫 등록 화면과 옷장이 빈 상태에서 알린다. 이미 담은 옷을 빼는 방법은 삭제로 충분하다(CLO-01, CLO-07).

### REG-02 등록 경로
| 경로 | 규칙 |
|---|---|
| 구매 확정 | ORD-02 |
| 상품 링크 | 상품 페이지에서 치수를 가져온다 |
| 구매내역 캡처 | 캡처에서 상품을 찾아 치수를 가져온다 |
| 사진 측정 | REG-05 |
| 직접 입력 | 사이즈표 붙여넣기를 지원한다 |

- 상품 링크와 캡처가 실패하면 실패 이유를 보여 주고, 사이즈표 붙여넣기와 직접 입력을 권한다.
- 지원 쇼핑몰 목록은 보여 주지 않는다.

### REG-03 다른 쇼핑몰 치수는 우리 측정 방식으로 본다
상품 링크, 캡처, 사이즈표 붙여넣기로 들어온 다른 쇼핑몰 치수는 DANGJANG 측정 방식(MEA-03)으로 잰 값으로 보고, 정상 범위만 검사한다(MEA-04). 사용자에게 그 쇼핑몰의 측정 방식을 묻지 않는다.

### REG-04 핵심 부위가 빠졌을 때
- 직접 입력은 핵심 부위가 모두 있어야 저장된다.
- 상품 링크나 캡처로 가져온 치수에 핵심 부위가 빠지면 치수 부족 옷(CLO-03)으로 담고, 빠진 칸을 채우도록 안내한다.

### REG-05 사진 측정
- 긴팔 셔츠, 긴팔 티셔츠, 후드티, 긴바지만 지원한다. 다른 세부 종류는 사진 측정 입구에서 직접 입력으로 안내한다.
- 측정에 실패하면 숫자를 지어내지 않고, 원인과 다른 등록 방법을 보여 준다.

### REG-06 치수 검증
- 등록, 사진 측정 결과, 정보 수정이 같은 검증 하나를 쓴다.
- 쉼표는 소수점으로 읽고, "56cm"처럼 단위가 붙은 값도 읽는다.
- 정상 범위(MEA-04)와 부위 간 관계(밑위 < 총장, 허리 < 엉덩이)를 본다.
- 틀리면 저장을 막고, 틀린 칸에 이유를 보여 주고, 첫 번째 틀린 칸으로 이동한다.

### REG-07 세부 종류를 고르지 않으면 담지 않는다
세부 종류는 꼭 골라야 한다(CAT-03). 고르지 않고 저장하면 막고, 세부 종류를 고르라고 알린다. 정보 수정에서 대분류를 바꿨을 때도 같다.

상품 링크나 캡처로 세부 종류를 자동으로 골랐으면, 자동으로 골랐다는 것을 보여 주고 사용자가 확인하고 바꿀 수 있게 한다. 자동으로 고르지 못하면 사용자가 고른다.

### REG-08 추정값을 만들지 않는다
빈 부위를 다른 부위 비율로 채우지 않는다. 빈 부위는 "정보 없음"이다.

### REG-09 치수 출처를 화면에서 구분하지 않는다
입점 브랜드, 다른 쇼핑몰, 사용자가 잰 값을 같은 치수로 보여 준다.

## 2. 비교와 추천 (REC)

### REC-01 추천 계산은 하나다
추천 계산 하나를 홈, 상품 상세, 옵션 시트, 장바구니, 주문서가 함께 쓴다. 결과는 사이즈, 부위별 차이, 비교한 부위, 추천 상태를 함께 돌려준다.

### REC-02 비교하는 부위
| 비교하는 두 옷 | 비교하는 부위 |
|---|---|
| 같은 세부 종류 | 두 옷 모두 잰 부위 전부 |
| 다른 세부 종류 (같은 대분류) | 그중 몸통 품 부위만 (CAT-07) |

빈 부위는 0으로 넣지 않고 점수에서 뺀다. 다른 대분류의 옷과는 비교하지 않는다(BASE-01).

치마와 바지는 서로 비교하지 않는다. 엉덩이를 재는 위치가 달라(MEA-03) 맞는 몸통 품 부위가 허리 하나뿐이기 때문이다.

### REC-03 점수
- 사이즈마다 부위별 차이에 가중치를 곱해 더하고, 가장 작은 사이즈를 고른다.
- 가중치는 부위 이름에 붙인다. 품 부위가 길이 부위보다 무겁다.
- 품 부위에서는 상품이 작은 쪽 차이를 큰 쪽 차이보다 무겁게 본다. 길이 부위는 같게 본다.
- 가중치 값은 검토 중이다.

### REC-04 판정
| 차이 | 판정 |
|---|---|
| 2cm 이내 | 비슷해요 |
| 4cm 초과 | 커요 / 작아요 |

모든 치수 출처에 같은 기준을 쓴다. 부위별 기준은 정답표 결과를 보고 다시 정한다.

### REC-05 판정 용어
| 층 | 쓰는 말 |
|---|---|
| 종합 판정 | 비슷해요 / 커요 / 작아요 |
| 길이 부위 | 길어요 / 짧아요 |
| 품 부위 | 넉넉해요 / 타이트해요 |

"넓어요", "딱 맞아요", 퍼센트는 쓰지 않는다.

### REC-06 추천 상태
| 상태 | 언제 |
|---|---|
| 추천 | 아래 어느 것에도 해당하지 않을 때 |
| 두 사이즈 사이 | 1위와 2위 점수 차이가 작을 때 (기준 값은 검토 중) |
| 맞는 사이즈 없음 | 가장 가까운 사이즈도 비교한 핵심 부위 중 하나가 4cm를 넘게 작을 때 |
| 가장 맞는 사이즈 품절 | 1위 사이즈가 품절일 때. 다음 사이즈를 함께 보여 준다 |
| 모든 사이즈 품절 | 모든 사이즈가 품절일 때 |

- 크기만 큰 경우는 "맞는 사이즈 없음"이 아니다. 추천하되 넉넉하다고 보여 준다.
- 상품과 기준 옷, 비교 옷 모두 핵심 부위가 있으므로(CAT-08, BASE-03, CMP-03) 비교할 부위가 모자라 추천하지 못하는 경우는 없다.

### REC-07 같은 종류와 다른 종류의 비교 화면
| | 같은 세부 종류 | 다른 세부 종류 (직접 고른 비교 옷) | 자동 비교 (CMP-04) |
|---|---|---|---|
| 추천 사이즈 | 보여 준다 | 보여 준다 | 보여 준다 |
| 추천 상태 (REC-06) | 보여 준다 | 보여 준다 | 보여 준다 |
| 비교 도식 | 내 옷과 상품을 겹쳐 그린다 | 상품만 그린다 | 그리지 않는다 |
| 부위별 판정 | 비교한 모든 부위 | 몸통 품 부위에만. 나머지 부위는 상품 치수만 보여 준다 | 보여 주지 않는다 |
| 알림 | 없음 | 어떤 옷을 기준으로 무엇을 비교했는지 알린다 | 어떤 옷과 몸통 품 부위만 비교했는지 알린다 |

기준 옷은 언제나 상품과 세부 종류가 같다(BASE-01). 그래서 다른 세부 종류 화면은 비교 옷을 직접 골랐거나 자동 비교일 때만 나온다.

### REC-08 비교 상태별로 알릴 것
| 비교 상태 (USR-03) | 알릴 것 |
|---|---|
| 기준 옷 있음 | 없음 |
| 자동 비교 | 어떤 옷과 무엇을 비교했는지(몸통 품 부위만). 그 세부 종류의 기준 옷을 등록하는 길. 다른 옷으로 바꾸는 길(교체하기) |
| 기준 옷 없음 | 그 세부 종류의 기준 옷을 등록하는 길 |

### REC-09 추천에 넣지 않는 것
- 오버핏, 신축성 같은 핏 의도는 반영하지 않는다. 오버핏 상품에는 크게 나오는 옷이라고 알린다.
- 후기는 반영하지 않는다.

### REC-10 홈의 옷장 기준 추천
- 상품 상세와 같은 계산(REC-01)을 쓰고, 품절 사이즈는 뺀다.
- 퍼센트 대신 종합 판정(REC-05)으로 보여 준다.
- 맞는 상품이 없으면 기준을 완화하지 않고, 지금은 맞는 상품이 없다고 알린다.
- 기준 옷 비교만 쓴다. 자동 비교(CMP-04)한 상품은 홈 추천에 넣지 않는다.

### REC-11 정답표
- 상품 치수와 기준 옷의 쌍 20~30개에 기대 결과(사이즈와 추천 상태)를 적는다. 같은 세부 종류 비교(기준 옷), 다른 세부 종류 비교(비교 옷), 자동 비교(CMP-04, 예: 긴팔 셔츠 → 긴팔 티셔츠, 반팔 티셔츠 → 긴팔 티셔츠, 숏코트 → 롱코트)를 모두 넣는다.
- 추천 규칙을 바꿀 때마다 정답표를 다시 돌려 맞은 개수를 본다.

## 3. 구매와 주문 (ORD)

### ORD-01 주문 상태는 하나의 값이다
```
배송 중 → 배송 완료 → 구매 확정 → 옷장 담김
               └→ 반품 신청
```
구매 확정, 반품, 옷장 담기 전에 지금 상태를 확인한다.

### ORD-02 구매 확정 뒤에 옷장 담기를 묻는다
구매 확정되면 "옷장에 담을까요?"를 묻는다(나중에 / 담기). 주문 내역에서도 담을 수 있다. 반품 신청한 주문은 담을 수 없다(CLO-04).

### ORD-03 자동 구매 확정
배송 완료 뒤 7일이 지나면 자동으로 구매 확정하고, 다음에 앱을 열 때 옷장 담기를 묻는다.

### ORD-04 주문에 추천 정보를 남긴다
추천 사이즈, 산 사이즈, 추천 상태, 비교 상태(USR-03)를 남긴다. 자동 비교의 정확도를 기준 옷 비교와 따로 보기 위해서다.

### ORD-05 구매 확정 때 핏을 묻지 않는다

### ORD-06 반품과 교환을 나눈다
교환할 때 기준 옷으로 사이즈 추천을 다시 보여 준다.

### ORD-07 장바구니에서 사이즈를 바꿀 때 추천을 보여 준다
REC-01과 같은 계산을 쓴다.

## 4. 개인정보와 동의 (PRIV)

### PRIV-01 받는 데이터
| 데이터 | 왜 받나 | 규칙 |
|---|---|---|
| 옷 치수 | 사이즈 비교 | 옷장에 처음 들어갈 때 동의를 받는다. 동의하지 않으면 옷장 기능을 쓸 수 없다고 알린다 |
| 옷 사진 | 사진 측정, 옷장 표시 | 보관하고 옷장 표시에 쓴다 |
| 구매내역 캡처 | 상품 찾기 | 상품을 찾은 뒤 원본은 보관하지 않는다. 캡처에는 주문번호, 이름 같은 개인정보가 들어간다 |
| 주문 데이터 | 구매 확정, 추천이 맞았는지 보기 | 추천 정보를 함께 남긴다(ORD-04) |

### PRIV-02 사용자가 넣지 않은 정보는 가져오지 않는다
사용자가 직접 넣지 않은 신체 정보나 옷 정보(예: 다른 서비스의 체성분 수치)는 가져오지 않는다.

### PRIV-03 탈퇴
법으로 보관해야 하는 기록만 정해진 기간 보관하고, 옷장, 치수, 옷 사진은 바로 지운다.

| 보관하는 기록 | 기간 |
|---|---|
| 계약 또는 청약철회에 관한 기록 | 5년 |
| 대금결제와 상품 공급에 관한 기록 | 5년 |
| 소비자 불만 또는 분쟁처리에 관한 기록 | 3년 |
| 표시·광고에 관한 기록 | 6개월 |

근거: 전자상거래 등에서의 소비자보호에 관한 법률 시행령 제6조제1항 (2026-07-21 시행본에서 확인).
