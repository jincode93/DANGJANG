# 평가 기준

결과물(데모, PRD, 정책 문서, 확장 기능 프로토타입)을 CEO, 디자이너, 엔지니어 세 관점에서 리뷰하는 기준을 사람이 읽기 쉽게 요약한 문서다. 신기능 제안서(`docs/proposals/`)는 이 기준이 아니라 `docs/eval/proposal-rubric.md`로 본다. 스킬이 실제로 따르는 지시는 각 스킬 파일에 있다.

기준은 gstack의 `plan-ceo-review`, `plan-design-review`, `plan-eng-review`를 DANGJANG에 맞게 고친 것이다. 출처와 라이선스는 `.claude/skills/NOTICE.md`에 있다.

## 점수 매기는 법 (gstack 0~10 방식)

1. 차원마다 0~10점을 준다.
2. "왜 N점인가"와 "10점이면 어떤 모습인가"를 DANGJANG에 맞게 구체적으로 쓴다.
3. 근거(화면 이름, 파일 위치, 문서의 절)를 붙인다. 근거가 없으면 5점을 넘을 수 없다.
4. 고칠 방법을 추천한다.

| 점수 | 뜻 |
|---|---|
| 10 | 더 정할 것이 없다 |
| 8 | 작은 구멍만 남았다 |
| 5 | 기본 흐름만 정해졌고 예외 상황은 비어 있다 |
| 3 | 생각은 있지만 정해지지 않았다 |
| 0 | 없다 |

- **대표 점수는 가장 낮은 차원의 점수다.** 평균이 높아도 한 차원이 비면 대표 점수가 낮다. 평균은 함께 적는다.
- **판정:** 대표 점수 8 이상이면 진행, 5~7이면 고치고 진행, 4 이하면 방향 재검토.
- **치명적 구멍:** 대응이 없고, 확인 방법도 없고, 사용자에게도 안 보이는 실패는 따로 센다.

## 관점별 차원

### CEO · 이걸 할 가치가 있나

| # | 차원 | 보는 것 |
|---|---|---|
| C1 | 전제와 기획 문장 대조 | 진짜 문제와 안 풀면 잃는 것. 문제를 직접 푸는가, 대리 지표만 푸는가. 기획 문장이 약속하는 것을 실제 기능이 다 해내는가, 아니면 문장을 좁혀야 하는가 |
| C2 | 기존 대안 | 이미 있는 해결책과, 그럼에도 만드는 이유 |
| C3 | 12개월 그림 | 1년 뒤 이상적인 모습, 되돌리기 쉬운 정도(1~5), 다른 기능의 기반이 되는가 |
| C4 | 범위 판단 | 확장 / 선택 확장 / 유지 / 축소 중 무엇이 맞는가. 넣은 것, 미룬 것, 뺀 것과 이유 |
| C5 | 실패 지도와 데이터 위험 | 기능마다 무엇이 잘못될 수 있고, 사용자에게 무엇이 보이고, 누가 확인하나. 받는 개인정보(치수, 사진, 구매내역 캡처, 주문 데이터)마다 목적, 실제로 거치는 동의 시점, 보관·삭제 규칙이 있나 |
| C6 | 예외 상황과 여정 | 빈 옷장, 같은 그룹 옷 없음, 부분 반품, 교환, 잘못된 입력, 품절. 첫 한 시간의 경험 |
| C7 | 측정과 검증 | 잘 된다는 신호와 망가졌다는 신호, 어디서 읽는가. 가장 위험한 가정을 검증할 합격선을 실행 전에 숫자로 정했나 (예: 10명 중 7명 이상이 도움 없이 첫 옷 등록) |

### 디자이너 · 처음 쓰는 사람이 바로 이해하나

| # | 차원 | 보는 것 |
|---|---|---|
| D1 | 정보 구조 | 화면마다 무엇을 먼저 보여 주나. 상품 상세에서 내 사이즈 판정이 3초 안에 보이나 |
| D2 | 상태 | 로딩, 비어 있음, 오류, 성공, 일부만. 기준 옷 없음, 실측 없음, 전부 품절 같은 DANGJANG 상태 |
| D3 | 여정과 감정 | 첫 방문부터 첫 비교까지. 등록하는 수고가 보상되나 |
| D4 | 구체성 | 한 단어는 한 뜻, 한 색은 한 뜻. 흔한 템플릿처럼 보이지 않나 |
| D5 | 디자인 기준 | 상품 상세 시안의 토큰과 컴포넌트를 모든 화면이 따르나 |
| D6 | 모바일과 접근성 | 터치 영역 44px, 글자 크기, 대비, 입력칸 라벨, 오류 표시 위치 |
| D7 | 미룬 결정 | 점수 없음. 미루면 구현에서 문제가 될 결정 목록 |

### 엔지니어 · 만들 수 있고, 틀리지 않나

| # | 차원 | 보는 것 |
|---|---|---|
| E1 | 구조와 데이터 흐름 | 등록부터 추천 표시까지 정상·값 없음·빈 값·앞 단계 실패 경로. 주문과 옷장의 상태 그림 |
| E2 | 규칙과 예외 | 단위 오류, 범위 밖 값, 중복, 기준 옷 변경·삭제, 입력 도중 나가기 |
| E3 | 코드 품질 | 중복된 로직, 삼켜진 오류, 근거 없는 숫자(가중치, 2cm·4cm 기준) |
| E4 | 실패 경로 | 경로마다 실패, 처리, 확인 방법, 사용자에게 보이는 것 |
| E5 | 확인 계획 | 흐름마다 정상·실패·경계값 확인. 금요일 밤에 배포해도 될 만큼의 확인은 무엇인가 |
| E6 | 실현 가능성 | 실측 데이터 확보, 사진 측정 정확도, 주문 데이터 연동, 개인정보 |
