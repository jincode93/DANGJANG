# gstack 원본과 우리 리뷰 스킬 비교 (CEO 리뷰)

> 결론: 두 리뷰는 핵심 문제 4개를 똑같이 찾았다. gstack은 더 넓고 깊었고(기획 문장의 과장, 검증 합격선, 개인정보), 우리 스킬은 더 빠르고 한국어로 점수를 남겼으며 gstack이 놓친 새 버그 하나를 찾았다. 둘 중 하나만 고르기보다 역할을 나눠 쓴다.

## 비교 조건

- 대상: 통합 데모 v14와 `CLAUDE.md`의 제품 설명, `docs/research/`
- 같은 날, 같은 모델, 서로 다른 세션에서 동시에 실행. 둘 다 질문 없이 끝까지 돌림
- gstack은 `plan-ceo-review` 원본(commit 188e574), 전략 수준 깊이. 질문할 자리에서는 스킬이 추천하는 답을 자동으로 고름
- 우리 스킬은 `review-ceo`, 보고서 모드

| 결과가 남는 곳 | 보고서 + 내 컴퓨터의 `~/.gstack` 기록 | `reviews/`와 `reviews/scores.csv` |

## 둘 다 찾은 것

1. 추천이 맞았는지 기록하는 장치가 없다. 실패한 옷은 반품되지 않아(인터뷰 0/4) 틀린 추천이 어디에도 드러나지 않는다.
2. 기준 옷에 잘못된 값 하나가 들어가면 그 그룹 추천이 전부 조용히 틀어진다 (점검 목록 A1).
3. 추정값과 빈 칸이 실측처럼 쓰이고, 한 부위만 겹쳐도 "비슷해요"가 나온다 (B3, B4).
4. 맞는 사이즈가 없어도 사이즈를 추천한다 (B2).

## gstack만 찾은 것

- **문제정의가 약속을 과하게 한다.** 문제정의 v3는 "사이즈는 맞는데 안 어울리는" 실패를 말하는데, 실측 비교는 기장·비율 실패만 풀고 어울림·색은 못 푼다. 문장을 좁혀야 한다.
- **"반품 감소"로는 효과를 증명할 수 없다.** 실패한 옷이 반품되지 않으니 플랫폼이 볼 반품 감소도 없다. 전환과 재구매 신뢰를 앞세우라고 했다.
- **검증 합격선.** 예: 참가자 10명 중 7명 이상이 도움 없이 첫 옷을 등록해야 통과.
- **핵심 지표 정의.** 같은 그룹 기준 옷이 있는 사용자의 상품 상세 조회 중 비교가 표시되고 추천 사이즈를 고른 비율.
- **개인정보.** 구매내역 캡처에 개인정보가 들어가고, 실측 데이터 동의가 선택으로 표시되지만 실제로 강제되지 않는다.
- 이미 알려진 버그(전부 품절 시 화면 오류 B5, "교체하기"가 아무것도 바꾸지 않음 B13)를 실패 지도에 넣었다.
- 작업별 소요 시간 추정(사람 기준, AI 기준)을 붙였다.

## 우리 스킬만 찾은 것

- **홈과 상품 상세의 추천 계산이 다르다 (새 버그).** 데모의 상품 데이터로 직접 계산해 보니, 홈 38쌍 중 1쌍에서 홈은 품절된 32를 "92% 비슷해요"로 보여 주고 상세는 30을 추천했다. 고치기 전 옛 스킬로 돌린 실행에서도 같은 버그를 찾아서, 우연이 아니라 재현되는 발견이다.
- 점검 목록 ★★★ 22개 중 9개가 핵심 기능이 아니라 주변 커머스 화면(주문서, 쿠폰 등)에 있다는 범위 판단.

## 각 방식의 약점

| gstack | 우리 스킬 |
|---|---|
| 코드 계획용 섹션(보안, 배포, 성능)까지 모두 돌아서 기획 리뷰에는 덜 중요한 내용이 섞인다 | 차원이 7개라 gstack보다 좁다. 기획 문장 검토나 개인정보 같은 영역을 놓쳤다 |
| 원래는 문제마다 사람에게 묻는 방식이다. 무인으로 돌리면 11개 결정을 스스로 골라서 "미해결 0"이 된다. 사람이 다시 확인해야 한다 | 점수가 이번이 처음이라 기준점이 없다. 같은 대상을 두 번 돌려 흔들림을 재 봐야 한다 |
| 다른 모델 의견(Codex), 웹 조사 도구(Aside)가 없어 일부 단계가 빠졌다. 한글 파일 이름을 근거로 인정하지 않는 문제도 있었다 | 스킬을 고친 뒤 같은 세션에서 부르면 옛 내용이 실행되는 문제가 있었다. 새 세션에서 쓰거나 파일을 직접 읽게 해야 한다 |
| 결과가 영어이고 레포 밖에 저장된다 | gstack 업데이트를 따라가려면 직접 맞춰야 한다 |

## 앞으로 쓰는 방법

- **매번 돌리는 빠른 점검:** 우리 스킬. 세 관점을 동시에 돌리고 점수를 `scores.csv`에 쌓아 v1 → v2 변화를 보여 준다.
- **중요한 결정 직전의 깊은 점검:** gstack 원본. 사람이 같이 앉아 질문에 답하는 방식으로 쓴다. 무인으로 돌리면 자동 결정을 꼭 다시 확인한다.
- **gstack에만 있는 도구:** `/qa`로 데모를 직접 눌러 보는 테스트, `/office-hours`로 확장 기능 아이디어 다듬기.
- **우리 스킬에 옮긴 것 (10/26):** 기획 문장 대조(C1), 개인정보·동의(C5), 검증 합격선(C7). 보고서에 해당 표 3개가 추가된다.
