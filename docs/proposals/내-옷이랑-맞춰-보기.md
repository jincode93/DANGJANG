# 내 옷이랑 맞춰 보기

- 제안한 사람: juribb
- 날짜: 2026-10-28

## 어떤 문제를 푸나요?

사이즈 비교는 "이 상품이 내 몸에 맞나"에 답한다. 그런데 장바구니에 담은 뒤에는 "이걸 사면 내가 가진 옷이랑 어떻게 입지?"가 남는다. 지금은 이 질문에 답할 곳이 없어서, 사용자는 다른 앱이나 머릿속으로 맞춰 본다.

근거는 아래와 같다.

- 솔루션 3안의 핵심 질문이 이것이었다: "이걸 사면 내 옷이랑 어떻게 입지?" 지금 기능의 검증을 먼저 하려고 로드맵으로 미뤘다. (`docs/research/06-솔루션-도출.md`)
- 멘토링 3회차: 옷장의 장기 목표는 코디이고, 그 첫 단계가 핏이어야 한다. (`docs/mentoring/3회차-2026-10-16.md`)
- 후기에서 착용 사진부터 보는 사람이 설문 24명 중 10명이었다. 숫자만큼 "입었을 때의 느낌"을 본다. (`docs/research/04-페인포인트-페르소나-HMW.md`)
- 쇼핑 취향 테스트에서 47명 중 21명이 "가진 옷과 코디가 어려움"을 골랐다. (가정: 이 테스트는 설문 24명과 다른 자료이고 아직 레포에 없다. 출처를 `docs/research/`에 올린 뒤 인용한다)

## 어떻게 푸나요?

장바구니 상품을 내 옷장의 옷과 한 바닥에 놓아 본다. 패션북(`docs/proposals/패션북.md`)이 내 옷만으로 꾸미는 곳이라면, 이 기능은 **사기 전에** 장바구니 상품을 그 위에 올려 보는 입구다. 패션북이 채택되면 저장한 결과는 패션북에 들어가고, 별도의 보관함을 만들지 않는다.

### 들어오는 곳
| 들어오는 곳 | 바닥에 처음 놓는 것 | 아래 목록 순서 |
|---|---|---|
| 장바구니 "내 옷이랑 맞춰 보기" | 체크한 장바구니 상품 1개 + 나머지 자리는 내 옷 | 장바구니 상품 → 내 옷장 |
| 내 옷장(패션북) 새로 만들기 | 내 옷만 | 내 옷장 → 장바구니 상품 |

- 장바구니에서 체크한 상품만 맞춰 보기와 주문하기에 쓴다. 장바구니 체크박스·전체 선택·선택 삭제는 일반 커머스 방식을 따른다.
- 다른 장바구니 상품을 누르면 그 상품의 자리(상의·하의·아우터)만 바뀐다. 나머지 옷은 그대로다.

### 처음 놓는 내 옷 고르기
BASE-01을 따라 대분류가 아니라 세부 종류의 기준 옷에서 고른다. 결과를 보고 고르지 않고, 같은 옷장이면 늘 같은 옷이 놓인다(CMP-04와 같은 방식).

| 순위 | 고르는 기준 |
|---|---|
| 1 | 장바구니 상품과 계절이 같은 그룹(긴팔·긴바지·아우터 / 반팔·반바지)의 세부 종류 기준 옷 |
| 2 | 같은 그룹의 나머지 옷 |
| 3 | 계절이 맞는 옷이 없으면 그 자리 대분류의 아무 내 옷 |
| 같은 순위 안 | 기준 옷이 먼저, 그다음 먼저 담은 옷 |

- 장바구니 상품이 반팔·반바지면 아우터 자리는 비워 둔다. 빈 자리는 그리지 않고, "아우터 놓기"로 추가한다.
- 그 자리에 놓을 내 옷이 하나도 없으면 비워 두고, 옷 등록으로 가는 버튼을 보여 준다(원칙 2). 등록을 마치면 보던 화면으로 돌아온다.

### 바닥
- 4:5로 고정한다. 나중에 스토리로 공유할 때는 위아래 여백을 붙여 9:16으로 내보낸다.
- 옷은 끌어서 옮기고, 누르면 맨 앞으로 온다. 맨 앞 옷을 한 번 더 누르면 바꿀 옷 목록이 열린다. 바꿀 옷 목록은 내 옷을 먼저 보여 준다.
- 배경은 5가지 색과 직접 고르기.
- 옷 크기는 총장(cm)에 같은 비율을 곱해 그린다. 너비는 사진 비율을 따르므로 실제와 다를 수 있다. 화면에 "길이만 실제 비율이에요"를 적는다(원칙 1).

### 저장
- 제목은 직접 쓰거나 자동 추천을 쓴다. 자동 추천은 계절 + 태그 + 대표 옷으로 만든다(예: "늦가을 출근룩, 울 코트").
- 계절은 옷에서 먼저 정하고(패딩 → 겨울, 코트 → 늦가을, 반팔에 아우터 없음 → 여름), 정할 수 없으면 지금 달로 정한다.
- 태그: #출근 #주말 #약속 #여행 #데일리
- 저장한 결과는 보기만 한다. "이 조합으로 새로 맞춰 보기"로 복사해 새로 만들고, 삭제할 수 있다. 저장한 뒤 장바구니 상품이 품절되거나 장바구니에서 빠져도 저장한 결과는 남고, 상품에 "품절" 등 상태를 표시한다.

## 지금 정책과의 관계

| 정책 | 관계 |
|---|---|
| BASE-01, BASE-02 | 바꾸지 않는다. 처음 놓는 옷을 고를 때 세부 종류의 기준 옷을 쓴다 |
| CMP-04 | 바꾸지 않는다. 고르는 순서를 정해 두는 방식을 따온다 |
| REC-05 (퍼센트를 쓰지 않는다) | 지킨다. 어울림 점수나 퍼센트를 보여 주지 않는다 |
| ORD-07 | 바꾸지 않는다. 맞춰 보기는 사이즈를 바꾸지 않고, 사이즈 추천은 장바구니와 상품 상세에서만 한다 |
| PRIV-01 | 채택되면 줄을 더해야 한다: 저장한 조합(옷, 위치, 배경, 제목, 태그)과 배경을 지운 옷 사진. 옷 사진 줄의 "옷장 표시에 쓴다"를 넘어서는지 정해야 한다 |
| PRIV-03 | 채택되면 탈퇴 때 저장한 조합도 바로 지운다는 줄이 필요하다 |
| 용어 | 새 용어를 만들지 않는다. "맞춰 보기"는 버튼 문구이고, 저장한 결과의 이름은 패션북 제안과 함께 정한다 |

사이즈 비교에는 영향이 없다. 맞춰 보기의 크기 비율은 보여 주기용이고, 추천 계산에 쓰지 않는다.

## 어떻게 검증하나요?

발표 범위(11/5) 밖이라 지금 기능의 유저 테스트가 끝난 뒤 검증한다(멘토링 4회차).

- 유저 테스트: 장바구니에 2개를 담은 참가자가 도움 없이 맞춰 보기를 열고, 상품 하나를 바꾸고, 저장한다. 합격선은 10명 중 7명 이상. (가정: 합격선은 팀이 테스트 전에 확정한다)
- 지표: 장바구니 상품 중 맞춰 보기에 올린 상품과 아닌 상품의 주문 비율. 맞춰 보기 저장 뒤 7일 안에 다시 연 비율.

## 아직 모르는 것

- 패션북과 한 기능으로 합칠지, 입구만 나눌지. 합친다면 저장한 결과의 이름은 무엇인지.
- 배경 지운 옷 사진을 누가 만드는지(자동, 판매자, 담당자). 상품 사진은 입점 때 받을 수 있지만, 내 옷 사진은 품질이 고르지 않다.
- 계절 그룹(긴팔·반팔 등)을 CAT의 그룹 8개와 그대로 맞출지.
- 너비가 실제와 다른 것을 사용자가 신뢰 문제로 받아들이는지.
