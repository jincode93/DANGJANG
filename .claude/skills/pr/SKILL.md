# PR 올리기와 보기

git·gh 명령은 Claude가 대신 실행한다. 사용자에게는 무엇을 했는지 쉬운 말로 알린다.

## 커밋하고 푸시해줘

"커밋하고 푸시해줘"는 브랜치에 커밋해 푸시하고 PR을 여는 것까지를 뜻한다.

1. 지금 브랜치가 `main`이 아닌지 본다. `main`이면 `이름/주제` 브랜치를 먼저 만든다.
2. 이 브랜치의 PR이 이미 합쳐졌으면 거기에 더하지 않는다. `main`에서 새 브랜치를 만들어 새 PR로 올린다.
3. 커밋하고 푸시한다. 강제 푸시는 하지 않는다.
4. PR 설명은 `.github/pull_request_template.md` 양식을 채운다.
5. 화면(`prototype/`) PR이면 vercel[bot] 미리보기 주소를 기다려 PR 설명과 사용자 답에 적는다. 신기능이면 `?f=기능id`를 붙인다.

## 다른 사람의 PR을 볼 때

- 화면 PR이면 미리보기 링크를 먼저 연다.
- 링크가 없거나 고쳐 보며 확인해야 하면 그 브랜치를 로컬로 받아 띄운다. 끝나면 원래 브랜치로 돌아온다.
- 의견은 PR 댓글로 남긴다. 다른 사람의 브랜치와 제안 파일은 고치지 않는다.

## 합치기

- PR은 코드 오너(jincode93)의 승인이 있어야 합쳐진다. 팀원은 서로 리뷰하고 댓글을 남길 수 있다.
- 관리자 PR은 관리자가 승인 없이 합칠 수 있다(`gh pr merge --squash --admin`). 이 예외는 PR을 합칠 때만 통하고 직접 푸시에는 통하지 않는다. 합치는 것은 관리자가 따로 말할 때만 한다.
- 팀원 PR을 합치기 전에 관리자가 그 PR 브랜치에 `logs/decision-log.md`, `reviews/scores.csv` 줄을 더한다.
