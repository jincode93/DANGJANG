## 정해야 할 것

### 결정 1. 발표 전에 성공·실패 지표를 정하고 기록 설계를 할지
- 문제: 효과를 증명할 숫자가 없다(발견 1·5). 반품률로는 이 서비스의 효과가 보이지 않는다.
- A) 기능별 지표 3~5개와 출처, 읽는 시점을 한 장으로 정하고, 주문에 추천 사이즈를 남긴다 (추천) — 노력 S, 위험 낮음, 유지보수 낮음(문서 한 장과 주문 필드 하나)
- B) 지표 문서만 쓰고 데모는 그대로 둔다 — 노력 S, 위험 중간(발표에서 "어떻게 아나"에 답이 약함)
- C) 그대로 둔다 — 노력 없음, 위험 높음(효과도 고장도 보이지 않음)
- 추천 이유: "지표와 읽는 법은 출시 범위다, 다듬기가 아니다"(prime directive 3).

### 결정 2. 구매 확정 때 "추천 사이즈가 맞았나요?"를 물을지
- 문제: 추천이 맞았는지 아는 유일한 시점이 구매 확정이다(발견 1). 확정된 결정 "등록할 때 핏을 묻지 않는다"는 옷장 분류 규칙이고, 이 질문은 추천을 측정하는 질문이다. 새 근거는 반품 0/4다. 반품이 실패를 보여 주지 못한다.
- A) 확정 모달에 한 번 누르는 질문(잘 맞아요 / 커요 / 작아요)을 넣고, "잘 맞아요"일 때만 옷장 담기를 이어서 묻는다 (추천) — 노력 S, 위험 낮음(한 단계 늘어남), 유지보수 낮음
- B) 확정 며칠 뒤 알림으로 따로 묻는다 — 노력 M, 위험 중간(응답률 낮음)
- C) 그대로 둔다 — 노력 없음, 위험 높음(정확도 신호가 없음)
- 추천 이유: "조용한 실패는 없어야 한다. 모든 실패는 사용자, 팀, 지표 중 하나에 보여야 한다"(prime directive 1).

### 결정 3. 남은 열흘의 범위를 핵심으로 묶을지
- 문제: ★★★가 커머스 외곽까지 퍼져 있다(발견 7).
- A) 핵심(B2·B3·B4·B5, A1, A4, E4)만 고치고 커머스 외곽은 "흉내만"으로 명시한다 (추천) — 노력 M, 위험 낮음, 유지보수 낮음
- B) 점검목록의 ★★★를 순서대로 고친다 — 노력 XL, 위험 높음(핵심이 덜 다듬어진 채 발표)
- C) 그대로 둔다 — 노력 없음, 위험 중간
- 추천 이유: 유지 모드에서는 범위를 넓히지 않고 실패와 예외를 잡는다.

### 결정 4. "맞는 사이즈 없음"을 보여 줄지 (점검목록 B2)
- 문제: 어느 사이즈도 맞지 않아도 추천이 붙는다(발견 4).
- A) 핵심 부위(가슴·허리 등)가 허용 범위를 넘으면 추천 대신 "맞는 사이즈가 없어요"와 가장 가까운 사이즈의 차이를 보여 준다 (추천) — 노력 S~M, 위험 낮음, 유지보수 중간(그룹별 기준값 필요)
- B) 추천은 두고 "차이가 커요" 경고만 붙인다 — 노력 S, 위험 중간
- C) 그대로 둔다 — 노력 없음, 위험 높음(틀린 추천이 신뢰를 깎음)
- 추천 이유: 틀린 확신보다 "모른다"가 신뢰를 덜 잃는다. 조용한 실패를 보이는 실패로 바꾼다(prime directive 1).

### 결정 5. 홈 추천과 상세 추천의 계산을 하나로 할지
- 문제: 같은 기준 옷인데 홈과 상세가 다른 사이즈를 말할 수 있다. 홈은 품절 사이즈도 보여 준다(발견 6).
- A) 홈도 상세와 같은 계산(`recOf`)을 쓰고 품절을 뺀다. "% 비슷해요"는 그 결과로 만든다 (추천) — 노력 S, 위험 낮음, 유지보수 낮음(계산 한 곳)
- B) 계산은 두고 홈에서 품절만 뺀다 — 노력 S, 위험 중간(다른 어긋남이 남음)
- C) 그대로 둔다 — 노력 없음, 위험 중간
- 추천 이유: 나중에 일이 어려워지는 결정을 지금 막는다. 계산이 두 곳이면 고칠 때마다 두 번 고친다(prime directive 4).

### 결정 6. 구매 자동 확정을 둘지 (점검목록 E4)
- 문제: 확정을 누르지 않으면 옷장이 저절로 차는 흐름이 끊긴다(발견 9).
- A) 배송 완료 뒤 정해진 기간이 지나면 자동 확정하고, 다음 앱 실행 때 결정 2의 질문과 옷장 담기를 묻는다 (추천) — 노력 S, 위험 낮음, 유지보수 낮음
- B) 홈 카드와 알림만 강화한다 — 노력 S, 위험 중간
- C) 그대로 둔다 — 노력 없음, 위험 중간
- 추천 이유: "사용자가 첫 옷을 왜 등록하나"에 대한 가장 가벼운 답이 구매한 옷이다. 이 경로가 끊기면 등록 부담이 다시 사용자에게 간다.

### 결정 7. 12개월 그림을 한 장으로 남길지
- 문제: 1년 뒤 모습이 없어 "이 작업이 어디로 가나"에 답하기 어렵다(발견 11). 최종 발표 항목에 "실행 로드맵"이 있다(`docs/timeline.md` 11/5).
- A) 아래 "12개월 그림"을 바탕으로 로드맵 한 장을 만든다. 옷장 데이터를 다시 쓰는 기능(목록 배지, 교환 재추천, 반품 사유)과 되돌리기 어려운 결정을 표시한다 (추천) — 노력 S, 위험 낮음, 유지보수 낮음
- B) 발표 자료에만 넣는다 — 노력 S, 위험 낮음(레포에 근거가 안 남음)
- C) 그대로 둔다 — 노력 없음, 위험 중간
- 추천 이유: 6개월 뒤를 보고 결정한다(prime directive 4).

| 옷장 등록 | 첫 등록 완료율, 등록 경로별 완료율, 첫 등록까지 걸린 시간 | 경로별 중간 이탈, 범위 밖 값 경고 비율 | 등록 화면 이벤트 (지금 없음). 이번 주 사용성 테스트에서 관찰로 첫 값 |
| 상세 비교 | "비교 완료" 상태로 상세를 본 비율 | "같은 그룹 없음"·"실측 없음" 상태 비율 | 상세 상태값(`judge().n`)을 기록 (지금 없음). 주 1회 |
| 사이즈 추천 | 추천 사이즈 구매율, 구매 확정 때 "잘 맞아요" 비율 | "커요/작아요" 비율, 추천 사이즈 구매 뒤 사이즈 사유 반품률 | 주문의 추천 사이즈 필드(결정 1) + 확정 질문(결정 2). 확정이 쌓이는 월 1회 |
| 홈 추천 | 홈 추천 카드 → 상세 → 구매 전환 | 홈 사이즈와 상세 추천이 다른 비율 | 카드 노출·클릭 이벤트, 대조 점검(결정 5) |
| 구매 확정 → 옷장 | 확정 뒤 옷장 담기 비율, 구매로 채워진 옷 수 | 배송 완료 뒤 확정까지 기간이 길어짐, "나중에" 비율 | 주문 상태 기록. 월 1회 |
| 전체 문제 해결 | 방치 자가 응답이 줄어듦 (`01-문제정의.md` 6절 가정) | 재구매율 하락, 상세 → 구매 전환 하락 | 분기 설문. 판단 기준 숫자는 확인할 것 |

각 지표가 바꾸는 결정: 등록 경로 이탈 → 경로 우선순위와 사진 측정 유지 여부(멘토 3회차 지적). "커요/작아요" 비율 → 가중치·허용 오차(B1·B8) 조정. 확정까지 기간 → 자동 확정 기간(결정 6).
