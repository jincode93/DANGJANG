## 1. 데모 구조 요약 (구현 전에 알아 둘 것)

### 1.1 코드 구조

| 구성 | 데모 코드 | 설명 |
|---|---|---|
| 상태 | `S` (`reset()`에서 만듦) | 옷장 `S.closet`, 등록 대기 `S.pending`, 주문 `S.orders`, 장바구니 `S.cart` 등. 메모리에만 있어 새로고침하면 처음으로 돌아감 |
| 옷 한 벌 | `item()` | `id, cat, sub, size, m(치수 배열), fit, base, subBase, brand, pid, src, img, notes, at` |
| 화면 | `SCR.이름` | `SCR.closet`(내 옷장), `SCR.item`(옷 상세), `SCR.edit`(정보 수정), `SCR.fit`(핏 알려 주기), `SCR.detail`(상품 상세), `SCR.orders`(주문 내역) 등 |
| 동작 | `A.이름` | 버튼의 `data-a` 값과 같은 이름. 예: `A.saveEdit`, `A.confirmOk`, `A.ordAdd` |
| 화면 그리기 | `render()`, `go()`, `back()`, `tab()`, `modal()`, `sheet()`, `toast()` | 화면 이동과 팝업 |
| 분류와 부위 | `SUBS`, `GPARTS`, `partsOf()`, `grpOf()`, `NEED` | 세부 종류 15개, 치수 양식 8개, 양식별 부위, 필수 부위 |
| 비교 | `judge()`, `recOf()`, `deltaOf()`, `TOL = 2` | 상품 상세의 비교 상태, 추천 사이즈, 부위별 차이, 허용 오차 |
| 기준 옷 | `baseOf()`, `subBaseOf()`, `ensureBases()`, `compareSheet()` | 기준 옷 찾기, 자동 지정, 바꿀 때 비교 시트 |

### 1.2 데모와 팀 정책이 다른 곳 (기능을 붙이기 전에 정할 것)

| 항목 | 데모 | 팀 정책 | 이 문서의 처리 |
|---|---|---|---|
| 기준 옷 단위 | 치수 양식(8개) 단위 + 세부 종류 기준은 선택 | 세부 종류(15개)마다 하나 (BASE-01) | 새 기능은 정책대로 **세부 종류** 단위로 계산한다 |
| 안 맞는 옷 | "핏 알려 주기"에서 안 맞아요를 고르면 옷장에서 뺌 (`saveFit`) | 등록 때 핏을 묻지 않음 (CLO-01), 구매 확정 때 핏을 묻지 않음 (ORD-05) | 기능 4에서 다룬다 |
| 기준 옷 치수 수정 | 확인 없이 바로 저장 (`A.saveEdit`) | 확인창에 치수 차이를 보여 줌 (BASE-05) | 기능 6에서 함께 맞춘다 |
| 브랜드 | 옷에 `brand`가 있음 | 옷 정보에 브랜드가 없음 (CLO-02) | 기능 3에서 정책에 추가한다 |
| 코디북 | 버튼만 있고 "준비 중" 알림 (`A.cbook`) | 패션북 제안 (Vercel 데모에 구현) | 기능 5는 Vercel 데모 코드를 확인한 뒤 붙인다 |

### 1.3 이미 있어서 다시 쓸 수 있는 코드

- `A.fitPart`: 핏 알려 주기에서 부위별 응답을 받는 동작이 정의돼 있지만 화면에서는 쓰지 않는다. 기능 4의 부위와 방향 받기에 쓸 수 있다.
- `A.regFitAns`, `A.regNote`: 등록 대기 옷의 핏과 메모를 받는 동작이 남아 있다. 지금 `SCR.regFit` 화면에서는 쓰지 않는다.
- `item()`의 `notes` 필드: 옷마다 메모 배열이 이미 있다.
- `SCR.ordered`와 `SCR.orders`가 코드에 두 번씩 정의돼 있다. 뒤의 것이 쓰이므로, 기능을 붙이기 전에 앞의 것을 지워 두는 것이 좋다.

## 3. 기능별 구현 방안

### 기능 1. 기준 옷 채우기 현황

**붙는 곳:** 내 옷장(`SCR.closet`) 대분류 탭 아래, 세부 종류 칩 위에 접을 수 있는 카드 한 장

**화면 흐름**

1. 내 옷장을 열면 지금 탭(상의, 하의, 아우터)의 세부 종류별 상태가 한 줄씩 보인다.
2. 각 줄: 세부 종류 이름, 상태(기준 옷 있음 / 자동 비교 / 기준 옷 없음), 오른쪽 버튼
3. 기준 옷 없음이나 자동 비교 줄의 버튼 [등록하기]를 누르면 그 세부 종류가 미리 골라진 채로 옷 등록이 열린다.
4. 등록을 마치면 내 옷장으로 돌아와 상태가 바뀐 것을 보여 준다.

**계산 (새 함수 `baseStatus(cat)`)**

```
세부 종류마다
  그 세부 종류에 잘 맞는 옷(fit = good)이 있고 기준 옷이 있으면 → 기준 옷 있음
  같은 대분류에 다른 잘 맞는 옷이 있으면                       → 자동 비교 (CMP-04)
  없으면                                                         → 기준 옷 없음
  덧붙임: 그 세부 종류의 판매 상품 수 (PB에서 sub로 셈)
```

- 문구 예: "긴바지 기준 옷을 넣으면 긴바지 상품 4개를 모든 부위로 비교해요" (데모 상품 목록의 긴바지는 4개)

**고칠 코드**

| 위치 | 할 일 |
|---|---|
| `SCR.closet` | 카드 HTML 추가, 접힘 상태는 `S.ui.baseCard`에 저장 |
| 새 함수 `baseStatus(cat)` | 위 계산 |
| `startReg(cat, from)` | 세부 종류를 미리 고를 수 있게 인자 하나 추가 (`S.reg.sub`) |
| `A.regExit` | 시작한 곳이 내 옷장이면 내 옷장으로 돌아오기 (지금도 대부분 그렇게 동작) |

**정책:** 바뀌는 것 없음. CMP-04, USR-03의 상태 이름을 그대로 쓴다.

**확인할 것**

- 15개를 모두 보여 줄지, 옷이 있는 세부 종류만 보여 줄지
- 데모의 기준 옷이 치수 양식 단위라서, 세부 종류 단위로 계산하면 데모의 다른 화면과 상태가 다르게 보일 수 있다 (1.2 참고)

### 기능 2. 내 치수 범위

**붙는 곳:** 내 옷장에서 세부 종류 칩을 골랐을 때, 옷 선반 아래에 카드 한 장

**화면 흐름**

1. 세부 종류 칩(예: 긴바지)을 누른다.
2. 그 세부 종류의 잘 맞는 옷이 2벌 이상이면 "내 치수 범위" 카드가 보인다.
3. 카드: 부위 / 범위 / 벌 수. 예: 허리 40~42cm (4벌), 밑위 29~31cm (4벌), 총장 101~106cm (4벌)
4. 1벌뿐이면 "잘 맞는 옷이 2벌 이상이면 범위를 보여 드려요"를 보여 준다.

**계산 (새 함수 `fitRange(cat, sub)`)**

```
옷들 = 세부 종류가 sub이고 fit = good인 옷
부위마다 (partsOf 순서)
  값들 = 옷들의 그 부위 치수 중 0이 아닌 것
  값이 2개 이상이면 → 최솟값, 최댓값, 개수
  아니면 → 표시하지 않음
```

- 부위 이름은 지금 옷 상세에서 쓰는 `LONG` 표기를 그대로 쓴다.
- 추천 계산(`judge`, `recOf`)은 건드리지 않는다.

**고칠 코드**

| 위치 | 할 일 |
|---|---|
| `SCR.closet` | `sv`(고른 세부 종류)가 있을 때 선반 아래에 카드 추가 |
| 새 함수 `fitRange(cat, sub)` | 위 계산 |

**정책:** 바뀌는 것 없음.

**확인할 것**

- 오버핏과 레귤러가 섞이면 범위가 넓어진다. 데모 데이터에는 핏 의도 정보가 없어서 지금은 구분할 수 없다 (REC-09).
- 나중에 범위를 판정에 쓰려면 `judge()`를 바꿔야 한다. 이번에는 하지 않는다.

### 기능 3. 브랜드별 내 사이즈

**붙는 곳:** 내 옷장 상단 오른쪽 [브랜드별 사이즈] 버튼 → 새 화면 `SCR.brands`. 상품 상세 비교 영역 아래 한 줄

**화면 흐름**

1. 내 옷장에서 [브랜드별 사이즈]를 누른다.
2. 브랜드마다 한 줄: 브랜드 이름, 그 브랜드 옷의 세부 종류와 사이즈 칩. 예: 무신사 스탠다드 / 긴팔 셔츠 L, M / 긴바지 30
3. 칩을 누르면 그 옷의 옷 상세(`SCR.item`)로 간다.
4. 상품 상세에서는 옷장에 같은 브랜드, 같은 세부 종류 옷이 있으면 한 줄을 보여 준다: "이 브랜드 긴팔 셔츠는 L을 입고 있어요"

**데이터**

| 등록 경로 | 브랜드 |
|---|---|
| 구매 확정 (`addToCloset`) | 상품의 `brand`가 이미 들어감 |
| 상품 링크, 캡처 | 읽어 온 값. 확인 화면에서 고칠 수 있게 함 |
| 직접 입력, 사진 측정 | 선택 입력 칸을 새로 추가 |
| 정보 수정 (`SCR.edit`) | 브랜드 칸 추가 |

**고칠 코드**

| 위치 | 할 일 |
|---|---|
| 새 화면 `SCR.brands` | `S.closet`을 `brand`로 묶어 그리기. 브랜드가 없는 옷은 "브랜드 없음"으로 묶음 |
| `SCR.closet` | 상단에 버튼 추가 |
| `SCR.edit`, `A.saveEdit`, 직접 입력 화면 | 브랜드 입력 칸과 저장 |
| `SCR.detail` | 같은 브랜드, 같은 세부 종류 옷이 있을 때 한 줄 추가 |

**정책:** CLO-02 "옷이 가지는 정보"에 "브랜드(선택)"를 추가한다.

**확인할 것**

- 브랜드 이름 표기가 제각각일 수 있다 (예: "무신사 스탠다드"와 "무신사 스탠다드 우먼"). 묶는 기준을 정해야 한다.
- 상품 상세의 한 줄이 기준 옷 비교 결과와 다르게 말할 수 있다 (예: 브랜드로는 L, 비교 추천은 M). 이때 어느 쪽을 앞에 둘지 정해야 한다.

### 기능 4. 안 맞았던 옷 기록 (추가 기능)

**붙는 곳:** 기록하는 곳 3개, 보는 곳 2개

| 구분 | 화면 | 내용 |
|---|---|---|
| 기록 | 구매 확정 팝업 (`A.confirmOk`) | [나중에] [옷장에 담기]에 [안 맞았어요] 추가 |
| 기록 | 핏 알려 주기 (`SCR.fit`) | 안 맞아요를 고르면 옷장에서 지우는 대신 안 맞았던 옷으로 옮김 |
| 기록 | 옷 등록 확인 (`SCR.regFit`) | 옷마다 "안 맞았던 옷으로 기록" 선택 |
| 보기 | 내 옷장 (`SCR.closet`) | 맨 아래 "안 맞았던 옷 n벌" 줄 → 목록 화면 `SCR.misfit` |
| 보기 | 상품 상세 (`SCR.detail`) | 비교 결과 아래 주의 안내 |

**화면 흐름 (구매 확정에서 기록하는 경우)**

1. 구매 확정 → "내 옷장에 담아 둘까요?" 팝업에 [안 맞았어요]가 보인다.
2. 누르면 시트가 열린다: "어디가 안 맞았나요? (선택, 최대 2개)"
3. 부위 칩을 고르면 방향 칩이 나온다. 품 부위는 [작아요] [커요], 길이 부위는 [짧아요] [길어요] (CAT-06)
4. [저장] 또는 [건너뛰기] → "안 맞았던 옷으로 기록했어요. 비슷한 상품을 볼 때 알려 드릴게요"

**데이터 (새 목록 `S.misfit`)**

```
S.misfit = [
  { id, pid, brand, name, cat, sub, size, m(치수 배열),
    fails: [ { part: '밑위', dir: 'short' }, ... ],   // 최대 2개, 비어 있어도 됨
    from: 'order' | 'fit' | 'reg', at }
]
```

- 옷장(`S.closet`)과 **따로 둔다.** 옷장 목록, 기준 옷, 자동 비교, 코디북, 홈 추천이 모두 `S.closet`만 보므로, 따로 두면 이 화면들을 고칠 필요가 없다. 잘 맞는 옷만 담는 원칙(CLO-01)도 옷장 안에서는 그대로 지켜진다.
- 주문에는 `o.misfit = true`를 남긴다. 추천 정보(ORD-04)와 함께 "안 맞았던 주문 비율"을 셀 수 있다.

**주의 안내 계산 (새 함수 `misfitWarn(p, size)`)**

```
같은 세부 종류(sub)의 안 맞았던 옷마다
  기록된 부위와 방향마다
    상품 값 = 상품의 그 사이즈, 그 부위 치수
    옷 값   = 안 맞았던 옷의 그 부위 치수
    방향이 작아요 또는 짧아요 → 상품 값 ≤ 옷 값 + 2.0 이면 안내
    방향이 커요 또는 길어요   → 상품 값 ≥ 옷 값 − 2.0 이면 안내
안내 문구: "지난번 안 맞았던 {이름} {사이즈}과 {부위}가 비슷해요"
```

- 2.0은 데모의 `TOL`과 같은 값을 쓴다.
- `judge()`, `recOf()`는 바꾸지 않는다. 추천 사이즈와 추천 상태는 그대로이고, 안내만 덧붙인다.
- 사이즈 칩을 바꾸면(`view`가 바뀌면) 안내도 다시 계산한다.

**고칠 코드**

| 위치 | 할 일 |
|---|---|
| `reset()` | `S.misfit = []` 추가. 프리셋에 예시 1~2벌 추가 |
| `A.confirmOk` | 팝업에 [안 맞았어요] 버튼 추가 → 새 동작 `A.ordMisfit` |

### 기능 5. 코디북에 사려는 상품 올려 보기

**붙는 곳:** 상품 상세 하단, 장바구니 상품 줄, 코디북 판

**전제:** 이 데모의 코디북은 "준비 중" 알림만 있다 (`A.cbook`). 실제 코디북은 Vercel 데모(https://dangjang-demo.vercel.app)에 있으므로, 아래는 그 코드를 확인하기 전의 설계다.

**화면 흐름**

1. 상품 상세나 장바구니에서 [내 옷이랑 입어 보기]를 누른다.
2. 코디북 새 판이 열리고, 그 상품이 판 가운데 놓여 있다. 옷 도구에서 내 옷장 옷을 더 넣는다.
3. 판 위 상품에는 "아직 안 산 상품" 표시와, 누르면 상품 상세로 가는 버튼이 있다.
4. 저장하면 일반 코디북과 같이 남는다.
5. 나중에 그 상품을 사서 옷장에 담으면(`addToCloset`), 판의 상품 항목을 옷장 옷으로 바꾼다.

**데이터**

```
코디북 판의 항목 = { kind: 'closet', cid }          // 지금
                 | { kind: 'product', pid, size }   // 추가
```

**고칠 코드 (Vercel 데모 코드 확인 필요)**

| 위치 | 할 일 |
|---|---|
| `SCR.detail`, `SCR.cart` | [내 옷이랑 입어 보기] 버튼 |
| 코디북 판 | 상품 항목 그리기, 표시, 상품 상세로 가는 버튼 |
| `addToCloset` | 같은 상품, 같은 사이즈를 판에서 찾아 옷장 옷으로 바꿈 |
| 공유 링크 | 상품 항목을 넣을지, 상품 번호와 사이즈만 넣을지 결정 |

**정책:** 패션북 제안의 "패션북은 옷장에 있는 옷만 넣는다"에 예외를 둘지 정한다. CLO-01과는 부딪히지 않는다 (상품을 옷장에 넣지 않음).

**확인할 것**

- 코디북 코드가 판 항목을 어떤 구조로 저장하는지
- 사이즈를 고르지 않은 상품을 판에 올릴 때, 추천 사이즈를 넣을지 빈 채로 둘지

### 기능 6. 치수 다시 재기와 변경 기록

**붙는 곳:** 옷 상세(`SCR.item`)의 [치수 다시 재기] 버튼, 정보 수정(`SCR.edit`), 옷 상세 아래 "치수 변경 기록"

**화면 흐름**

1. 옷 상세에서 [치수 다시 재기]를 누른다.
2. 정보 수정 화면이 실측 칸으로 바로 열리고, 맨 위에 이유 칩이 보인다: [세탁 후] [잘못 쟀어요] [기타]
3. 저장할 때 기준 옷이면 지금 값과 새 값의 차이를 보여 주는 확인창을 띄운다 (BASE-05). 데모의 `compareSheet()` 모양을 그대로 쓴다.
4. 저장 후 옷 상세 아래 "치수 변경 기록"에 날짜, 이유, 바뀐 부위가 한 줄씩 쌓인다.

**데이터**

```
옷.hist = [ { at, reason: 'wash' | 'wrong' | 'etc', prev: [이전 치수 배열] }, ... ]
```

**고칠 코드**

| 위치 | 할 일 |
|---|---|
| `item()` | 기본값에 `hist: []` 추가 |
| `SCR.item` | 버튼과 기록 목록 추가 |
| `SCR.edit` | `pp.remeasure`일 때 이유 칩을 보여 주고 실측 칸으로 스크롤 |
| `A.saveEdit` | 치수가 바뀌었으면 `hist`에 이전 값 저장. 기준 옷이면 저장 전에 확인창 (지금은 확인 없이 저장함) |

**정책:** BASE-05에 "바꾼 치수는 이전 값과 날짜를 기록으로 남긴다"를 추가한다. 기록도 탈퇴 시 지운다 (PRIV-03).

**확인할 것**

- 기록을 몇 개까지 남길지
- 일반 정보 수정(이름, 사진)도 기록할지, 치수만 기록할지

## 4. 공통으로 정할 것

1. **기준 옷 단위:** 데모는 치수 양식 단위, 정책은 세부 종류 단위다. 기능 1, 2, 4를 세부 종류 단위로 만들면 데모의 기존 화면과 단위가 섞인다. 기능을 붙이기 전에 데모의 `baseOf()`를 정책에 맞출지 정한다.
2. **데모 데이터 유지:** 데모 상태는 메모리에만 있다. 시연 중 새로고침하면 기록이 사라지므로, 기능 4와 6을 시연하려면 프리셋에 예시 데이터를 넣어 둔다.
3. **측정 이벤트:** 데모에는 이벤트 기록이 없다. 각 기능의 검증 지표(등록 완료율, 안내 노출 등)는 실제 서비스에서 이벤트를 정의할 때 함께 정한다.
4. **중복 정의 정리:** `SCR.ordered`, `SCR.orders`가 두 번씩 정의돼 있다. 구매 확정 화면을 고치는 기능 4 전에 정리한다.
