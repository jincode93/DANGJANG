## 1. 상이한 내용

### 1.1 방향이 다른 규칙

| # | 주제 | 저장소 | v1.3 | 검토 의견 |
|---|---|---|---|---|
| D-01 | 안 맞는 옷 | 잘 맞는 옷만 담고, 안 맞는 옷 관리 기능은 두지 않아요. 반품한 옷도 담지 않아요 (CLO-01, CLO-04) | 체감 핏 3단계, 실패 의류를 보존하고 경고에 사용 | 가장 큰 차이예요. MVP로는 저장소 방식이 단순하지만, 인터뷰에서 나온 차별점 후보("실패 이후")가 빠져요 |
| D-02 | 핏 질문 | 구매 확정 때 핏을 묻지 않아요 (ORD-05) | 배송 후 14일간 핏 응답 요청 | 추천이 맞았는지 알 신호가 반품과 교환뿐이에요. 인터뷰에서 반품은 0건이었어요 (P-05, P-06에서 대안 제안) |
| D-03 | 기준 옷 단위 | 세부 종류(15개)마다 1벌 (BASE-01) | 비교 그룹(8개)마다 1벌 | 저장소가 더 정밀해요. 대신 자동 비교로 빈 곳을 메워요 |
| D-04 | 기준 옷이 없을 때 | 같은 대분류 옷으로 자동 비교하고, 몸통 품 부위만 비교 (CMP-04, REC-02) | 비교하지 않고 사이즈표만 | 저장소가 비교 범위가 넓어요. 자동 비교의 정확도는 따로 측정해요 (ORD-04) |
| D-05 | 기준 옷 자동 지정 | 처음 담은 치수 완료 옷이 자동으로 기준 옷이 돼요 (BASE-03) | 자동 지정 없이 물어봄 | 저장소는 확인창, 실행 취소, 알림으로 투명성을 확보해요. 저장소 방식을 따라도 된다고 봐요 |
| D-06 | 기준 옷 삭제 | 같은 세부 종류에서 먼저 담은 옷이 이어받고 알려요 (BASE-06) | 자동 이관 금지, "기준 옷 없음" | D-05와 같은 이유로 저장소 방식이 합리적이에요 |
| D-07 | 옷장에 넣는 시점 | 구매 확정 뒤 "옷장에 담을까요?"를 물어요. 배송 완료 7일 뒤 자동 구매 확정 (ORD-02, ORD-03) | 주문 완료 시 대기 상태로 자동 입고 | 저장소가 단순하고, 대기 상태가 없어요 |
| D-08 | 다른 쇼핑몰 치수 | DANGJANG 방식으로 잰 값으로 보고 정상 범위만 검사해요. 출처를 화면에서 구분하지 않아요 (REG-03, REG-09) | 출처마다 검증 상태를 두고 사용자 확인 후 사용, 출처 표시 | 링크와 캡처 값을 확인 없이 쓰므로, OCR 오류가 그대로 추천에 들어갈 수 있어요 (P-04에서 제안) |
| D-09 | 원피스 | 분류에 없어요 (CAT-01은 상의, 하의, 아우터) | 등록 허용, 비교 미지원 | 저장소 기준이면 원피스는 담을 수 없어요 (CAT-03) |
| D-10 | 범위 이탈 값 | 원인별 예외 없이 하나의 처리 (MEA-04) | 단면과 둘레 혼동은 확인 창으로 실험 | 저장소가 이미 결정했어요. v1.3 실험안은 내려도 돼요 |

### 1.2 용어 충돌

같은 단어가 두 문서에서 다른 뜻으로 쓰여요.

| 용어 | 저장소 | v1.3 |
|---|---|---|
| 핵심 부위 | 치수 양식마다 **꼭 있어야 하는 부위**. 예: 긴팔 상의는 총장, 가슴, 어깨, 소매 (CAT-08) | 수선이 어려워 **엄격하게 보는 부위**. 어깨, 가슴, 허리, 엉덩이, 허벅지, 밑위, 암홀 |
| 필수 부위 | 없음. 핵심 부위가 이 역할을 함 | 상의 총장과 가슴, 하의 총장과 허리 |

- v1.3의 "핵심 부위"는 저장소의 **몸통 품 부위**(CAT-07)에 밑위를 더한 것과 거의 같아요.
- 두 문서를 합칠 때는 저장소 용어를 따르고, v1.3의 "핵심 부위", "필수 부위"는 없애요.

### 1.3 저장소에만 있는 것

| 항목 | 규칙 |
|---|---|
| 부위별 측정 위치 표 | MEA-03 |
| 브랜드 보정 (둘레 ÷2, 화장 계산, 견본 1벌로 보정값 산출) | CAL-01~05 |
| 상품 검사 (자동 검사, 보류, 판매자 수정) | PRD-02 |
| 비교 옷 교체하기 (상품 하나에만 적용, 기준 옷은 그대로) | CMP-01 |
| 추천 상태 5가지 (추천, 두 사이즈 사이, 맞는 사이즈 없음, 1위 사이즈 품절, 모든 사이즈 품절) | REC-06 |
| 판정 용어 (품 부위는 넉넉해요, 타이트해요. "넓어요", "딱 맞아요", 퍼센트 금지) | REC-05 |
| 홈 옷장 기준 추천 | REC-10 |

| 개인정보 (법정 보관 기간 근거, 캡처 원본 미보관) | PRIV-01~03 |

### 1.4 v1.3에만 있는 것

| 항목 | 저장소 정책에서의 처리 |
|---|---|
| 실패 의류 경고 | CLO-01에 따라 해당 없음 (3장의 F-06으로 보류) |
| 핏 응답과 관련 지표 | ORD-05에 따라 해당 없음 (P-05, P-06으로 대체 제안) |
| 추천 동률 처리 순서 | REC-06 "두 사이즈 사이"로 대응. 기준 값은 검토 중 |
| 측정값 수정 이력 | BASE-05는 확인만 받고 이력은 없음 (F-04) |
| 응답 보상, 등록 쿠폰 조건 | 저장소에 없음 |
| 경계값 QA 시나리오 | P-09로 정답표에 추가 제안 |
| 데모 변경 요구사항 | P-07 (반팔 상의 어깨) 외에는 저장소 기준으로 다시 정리 필요 |

## 2. 제안 (저장소 정책 보완)

| # | 제안 | 이유 | 관련 규칙 | 우선순위 |
|---|---|---|---|---|
| P-01 | **2~4cm 구간의 판정을 정의** | REC-04 표에 "2cm 이내"와 "4cm 초과"만 있고, 2.0cm 초과 4.0cm 이하가 비어 있어요. 예: "살짝 넉넉해요, 살짝 타이트해요" | REC-04, REC-05 | 높음 (규칙 공백) |
| P-02 | **점수를 2cm 초과분으로 계산** | REC-03은 부위별 차이 전체를 더해요. 측정 오차(2cm) 안의 차이까지 점수에 들어가서, 판정은 "비슷해요"인데 순위가 바뀌는 일이 생겨요. "품 부위는 작은 쪽을 더 무겁게"는 그대로 유지해요 | REC-03 | 중간 |
| P-03 | **"맞는 사이즈 없음"을 몸통 품 부위 기준으로 한정** | REC-06은 "핵심 부위 중 하나가 4cm 넘게 작을 때"예요. 핵심 부위(CAT-08)에 총장과 소매가 있어서, 크롭 상품처럼 총장만 짧아도 "맞는 사이즈 없음"이 나와요. 의도한 것인지 확인이 필요해요 | REC-06, CAT-07, CAT-08 | 높음 (의도 확인) |
| P-04 | **링크와 캡처로 가져온 치수에 확인 단계 추가** | REG-07은 자동으로 고른 세부 종류만 확인시켜요. 치수도 "가져온 값을 확인해 주세요"를 한 번 거치면 OCR 오류를 막을 수 있어요. 출처를 화면에서 구분하지 않는다는 REG-09와는 충돌하지 않아요 | REG-03, REG-07, REG-09 | 중간 |
| P-05 | **반품과 교환 사유에 방향을 받기** | 핏 질문이 없으면(ORD-05) 추천 정확도를 볼 신호가 부족해요. 반품과 교환 때 "작아서, 커서, 길어서, 짧아서"만 받으면, 핏 질문 없이도 정답표와 실제 결과를 대조할 수 있어요 | ORD-04, ORD-06 | 중간 |
| P-06 | **옷장 담김을 긍정 신호로 기록** | 잘 맞는 옷만 담으므로(CLO-01), 구매 확정 뒤 "담기"는 사실상 "잘 맞아요"예요. 추천 사이즈로 산 주문의 담김률을 추천 적중률의 대리 지표로 쓸 수 있어요 | ORD-02, ORD-04, CLO-01 | 중간 |
| P-07 | **반팔 상의 어깨 부위를 데모에 반영** | 저장소는 반팔 상의에 어깨를 재지만, 데모의 반팔 상의 양식에는 어깨가 없어요 | CAT-05, CAT-08 | 높음 (구현 불일치) |
| P-08 | **허용 오차 2cm의 근거를 기록** | 무신사도 측정 오차를 약 2cm로 안내해요. REC-04의 근거로 적어 두면 정답표로 재검토할 때 출발점이 돼요 | REC-04, REC-11 | 낮음 |
| P-09 | **경계값 테스트를 정답표에 추가** | 2.0, 2.1, 4.0, 4.1cm 차이와, 품 부위와 길이 부위의 방향 문구를 정답표 케이스로 넣어요 | REC-11 | 낮음 |

## 3. 추가 기능 (출시 후 옷장)

### 3.1 저장소 원칙(잘 맞는 옷만)을 지키는 기능

| # | 기능 | 내용 | 관련 규칙 |
|---|---|---|---|
| F-01 | 재입고 알림 연결 | "가장 맞는 사이즈 품절"일 때 그 사이즈의 재입고 알림을 바로 걸 수 있게 해요. 데모에 재입고 알림이 이미 있어요 | REC-06 |
| F-02 | 기준 옷 여러 벌로 편한 범위 만들기 | 같은 세부 종류에 잘 맞는 옷이 2벌 이상이면, 부위별 최솟값과 최댓값으로 범위를 만들어 판정해요 | BASE-01 |
| F-03 | 브랜드별 사이즈 경향 | 주문 기록과 교환 방향으로 "이 브랜드는 평소보다 크게 나와요"를 보여 줘요 | ORD-04, P-05 |
| F-04 | 치수 수정 이력과 세탁 후 재측정 | 기준 옷이 줄었을 때 다시 재서 갱신하고, 이전 값을 남겨요 | BASE-05 |
| F-05 | 코디 매칭 | 옷장의 상의와 하의 조합 추천(Match Score)이에요. 비교 정책과 별개 기능이에요 | (신규) |

### 3.2 원칙을 바꿔야 하는 기능 (검증 후 판단)

| # | 기능 | 내용 | 충돌 규칙 | 검증 방법 |
|---|---|---|---|---|
| F-06 | 안 맞는 옷 참고 기록 | v1.3의 실패 의류 경고. 안 맞았던 옷의 부위와 방향을 기록해 비슷한 상품에 주의를 표시 | CLO-01, CLO-04, ORD-05 | 인터뷰에서 "실패한 옷 정보를 다음 구매에 쓰겠는가"를 과거 행동 기준으로 확인 |
