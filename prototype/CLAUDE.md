# 데모 작업 규칙

`prototype/` 파일을 읽거나 고칠 때 읽힌다. 폴더와 실행법은 `prototype/README.md`.

## 데모에 있는 것

팀 프로토타입 4개(홈, 상품 상세, 옷장 등록, 내 옷장)를 하나로 이은 앱. 결제와 로그인은 흉내만 낸다.

| 화면 | 하는 일 |
|---|---|
| 옷장 등록 | 기준 옷을 상품 링크, 구매내역 캡처, 사진 촬영 실측, 직접 입력으로 등록 |
| 상품 상세 | 기준 옷과 부위별로 비교. 어디가 넉넉하고 부족한지, 추천 사이즈 (데모는 아직 치수 양식 8개 단위로 비교함. 정책은 세부 종류 단위) |
| 홈 | 랭킹 상품 중 내 기준 옷과 실측이 가까운 상품 추천 |
| 내 옷장 | 등록한 옷 보기, 기준 옷 바꾸기, 정보 수정 |

사용자 상태: 계정(비회원/회원), 옷장(옷 없음/있음), 상품마다 비교 상태(기준 옷 있음/자동 비교/기준 옷 없음) 세 축으로 나눈다. 정의는 `docs/policy/02-대상과-상태.md`.

현재 추천 로직: 사이즈마다 `Σ |상품 − 기준 옷| × 가중치`를 계산해 점수가 가장 낮은 사이즈를 추천한다. 1·2번째 칸은 가중치 1.3, 나머지는 1. 품절 사이즈는 뺀다. 판정 낱말은 정책대로다(REC-04, REC-04-1, REC-05). 정책과 다른 점: 가중치는 칸 순서가 아니라 부위 이름(품 부위)에 붙이고(REC-03), 품절 사이즈도 계산에 넣어 가장 잘 맞는 사이즈가 품절이면 그대로 알린다(REC-06). 추천 상태(맞는 사이즈 없음, 두 사이즈 사이 등)는 아직 없다.

데모가 정책과 다르면 정책이 기준이다. 풀리지 않은 문제: `reviews/2026-10-26-출시수준-점검목록.md`

## 화면을 고칠 때

- `design-system/README.md`를 먼저 읽는다. 색·간격·글꼴·모서리·그림자는 토큰(`var(--…)`)만 쓰고 값을 직접 쓰지 않는다. 있는 컴포넌트(`.dj-*`)를 먼저 쓰고, 아이콘은 `design-system/icons/`만 쓴다. 디자인 시스템과 정책의 문구가 다르면 정책이 기준이고, 다른 점을 사용자에게 알린다.
- 신기능은 `prototype/public/features/기능/` 폴더와 `prototype/public/index.html`의 그 기능 한 줄만 고친다. 완료본(`app.js`, `app.css`)은 고치지 않는다. 끼울 자리가 더 필요하면 완료본에 자리만 여는 PR을 따로 올린다. 쓰는 법은 `prototype/public/features.js` 맨 위.
- PR 전에 로컬 미리보기로 확인한다. 미리보기 도구로 `.claude/launch.json`의 `dangjang-demo`를 띄운다(`node prototype/dev.mjs`, 기본 http://127.0.0.1:8792, 쓰는 중이면 빈 포트). 아티팩트에서 따로 고쳐 옮기지 않는다. 신기능은 주소에 `?f=기능id`(features.js의 `DJ.feature({ id })`)를 붙여 켠 채로 본다.
- PR을 올리면 미리보기 링크를 알린다. PR이 열리면 vercel[bot] 댓글에 미리보기 주소가 생긴다(1~2분). 신기능이면 `?f=기능id`를 붙여 PR 설명 "미리보기"와 사용자 답에 적는다. 미리보기는 로그인 없이 누구나, 폰에서도 열린다.
